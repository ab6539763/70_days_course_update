### 1.1 现场情况

周二站会，刘姐打开星火智服后台，指着文档列表：

| 问题 | 刘姐原话 | 影响 |
|------|----------|------|
| 200+ 份 txt/md 散落多目录 | 「不知道哪些文档在讲退款、大模型、工单」 | RAG 切块前无法做主题分布 |
| 人工打开统计不现实 | 「一份份 Ctrl+F 会累死」 | 无法给业务方出覆盖率报告 |
| 编码不统一 | 「有的 UTF-8，有的带 BOM，乱码就跳过」 | 统计漏文档 |
| 无时间戳报告 | 「我要能存档的 JSON，方便下周对比」 | 无法追踪文档变更影响 |

张工在白板上画了今日目标：

```text
  data/sample_docs/*.txt|md
        │
        ▼
  doc_keyword_stats.py  ← 批量读 + 正则统计
        │
        ▼
  output/keyword_report_YYYYMMDD_HHMMSS.json
```

然后转向培训生：

> 「Day 28 你们会用 LangChain 加载这些文档；**今天不碰向量库**，先把 **读文件、遍历目录、数关键词** 练到肌肉记忆。  
> 上午文件 IO；下午 pathlib 和正则；全天交付 CLI。」

### 1.2 与 Day 28 RAG 的关系

| 阶段 | 今日（Day 11） | Day 28 |
|------|----------------|--------|
| 输入 | 本地 txt/md 目录 | 同上 + PDF（后续） |
| 处理 | 全文读入、关键词计数 | 分块、Embedding、入库 |
| 输出 | JSON 统计报告 | 向量索引 + 检索 |
| 技术重点 | `pathlib`、`re`、UTF-8 | `DocumentLoader`、`TextSplitter` |

刘姐补充：

> 「统计报告能告诉我：**该不该把某批文档优先纳入 RAG**；命中率为 0 的可能是过期制度，命中过高的可能是重复副本。」

## 3. 与大模型开发的隐性联系

| 今日知识点 | 日后场景 |
|------------|----------|
| 批量读 txt/md | RAG 文档摄入管道第一步 |
| UTF-8 显式编码 | 中文语料不乱码、tokenizer 一致 |
| `pathlib.rglob` | 递归收集知识库文件 |
| `re` 关键词匹配 | 元数据提取、PII 脱敏规则 |
| `datetime` 报告时间戳 | 可观测、可对比的批处理作业 |
| `json.dump(ensure_ascii=False)` | 中文报告正确落盘 |
| 上下文管理器 `with` | 大文件流式读、句柄不泄漏 |

张工补充：

> 「向量检索之前，工程上常有一道 **ETL**：扫目录、过滤扩展名、统一编码、打标签。  
> 今天写的 `iter_text_files()`，三个月后你会在 `loader.py` 里几乎原样见到。」

## 4. 今日学习目标（业务语言）

1. 掌握 txt/csv/json 的读写，一律使用 `with` 与 `encoding="utf-8"`  
2. 熟练使用 `pathlib.Path` 做路径拼接、遍历、后缀过滤  
3. 能用 `re` 做简单关键词命中统计（含中文）  
4. 交付 `doc_keyword_stats.py`，对样例目录输出可核对 JSON 报告  
5. 向刘姐解释：为何统计工具是 RAG 上线前的「文档体检」
