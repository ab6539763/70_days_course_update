## 第一章 · 为什么需要函数

### 1.1 从重复代码到抽象

Day 2 你可能多次写了 `text.strip()`；Day 5 在三个字段上都调了清洗。函数把 **名字** 和 **逻辑** 绑在一起：

```python
def strip_edges(text: str) -> str:
    return text.strip()
```

调用方不必记住实现细节，只需记住契约：**str 进，str 出**。

### 1.2 函数的四个要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 名称 | 动词或动宾短语 | `clean_employee` |
| 参数 | 输入 | `raw: dict` |
| 返回值 | 输出 | `-> dict` |
| 文档 | docstring 说明用途 | `"""将单条员工记录清洗..."""` |

### 1.3 `def` 基本语法

```python
def function_name(param1: type1, param2: type2 = default) -> return_type:
    """文档字符串：Google 风格或单行均可。"""
    # 函数体
    return result
```

**注意**：`def` 行末尾的冒号与缩进四空格是硬性语法。

▶ 实操：阅读 `code/sparktech_cleaners/cleaners.py` 中每个函数的 docstring。

## 第二章 · 参数详解

### 2.1 位置参数（Positional）

按定义顺序传入，个数必须匹配（除非有默认值）：

```python
def add_todo(todos, next_id, title, priority="P1", tags=None):
    ...
```

调用：`add_todo(todos, 1, "写讲义")` —— `priority` 用默认 `"P1"`。

### 2.2 关键字参数（Keyword）

用 `名=值` 传递，顺序可调：

```python
add_todo(todos, 1, title="写讲义", priority="P0", tags=["day6"])
```

**可读性**：参数超过三个时，建议对非平凡参数使用关键字形式。

### 2.3 默认参数

```python
def greet(name: str, company: str = "星火科技") -> str:
    return f"欢迎加入{company}，{name}！"
```

**陷阱**：默认值在 `def` 执行时只求值一次。不要用可变对象作默认值：

```python
# 错误示范
def bad(tags=[]):  # 所有调用共享同一个 list！
    ...

# 正确写法
def good(tags=None):
    tags = tags or []
```

`sparktech_todo/core.py` 的 `tags: list[str] | None = None`  followed by `tags or []` 正是此模式。

### 2.4 仅关键字参数（Keyword-only）

`*` 之后的参数必须用关键字传递：

```python
def build_employee_line(name: str, employee_id: str, *, department: str) -> str:
    return f"{name} | {employee_id} | {department}"

build_employee_line("陈晓", "ST-001", department="大模型应用开发部")  # OK
# build_employee_line("陈晓", "ST-001", "大模型应用开发部")  # TypeError
```

`sparktech_cleaners.apply_pipeline` 中 `*, do_strip=False, ...` 强制调用方写出清洗开关，避免位置错乱。

### 2.5 `*args` — 可变位置参数

```python
def sum_numbers(*args: int) -> int:
    return sum(args)

sum_numbers(1, 2, 3, 4)  # args = (1, 2, 3, 4)
```

**场景**：参数个数不确定，如日志聚合、批量 ID 处理。

### 2.6 `**kwargs` — 可变关键字参数

```python
def merge_config(**kwargs: str) -> dict[str, str]:
    return dict(kwargs)

merge_config(model="qwen", temperature="0.7")
# {'model': 'qwen', 'temperature': '0.7'}
```

**场景**：透传配置给下层 API（Day 12 调 OpenAI 兼容接口时常见）。

### 2.7 参数顺序规则（背诵）

```text
def func(位置, /, 位置或关键字, *, 仅关键字, **kwargs):
```

培训阶段常用子集：

```text
def func(a, b, c=默认值, *args, key_only, **kwargs)
```

▶ 实操：运行 `python3 demo_functions.py`，对照输出理解 §2.1–2.6。

## 第三章 · 返回值

### 3.1 `return` 终止函数并带回值

```python
def format_bool_display(value: bool) -> str:
    return "是" if value else "否"
```

无 `return` 或 `return` 单独出现 → 返回 `None`。

### 3.2 返回多个值（实为元组）

```python
def complete_todo(todos, todo_id):
    ...
    return True, "已将 #1 标记为完成。"

ok, msg = complete_todo(todos, 1)
```

Day 6 重构将 Day 4 的 `print` 改为 **返回消息**，CLI 层负责展示——这是分层的关键一步。

### 3.3 返回新对象 vs 原地修改

| 模式 | 示例 | 适用 |
|------|------|------|
| 返回新 dict | `clean_employee(raw)` | 保留原始 Mock 数据对比 |
| 原地修改 list | `todos.append(item)` | 内存待办状态机 |

**张工规范**：清洗类函数返回新对象；状态容器（`todos` 列表）可原地修改但需在 docstring 标明。

### 3.4 类型注解

```python
def list_todos(
    todos: list[dict],
    filter_mode: str = "1",
    sort_by_priority: bool = False,
) -> list[dict]:
```

类型注解不强制运行时检查，但 IDE 补全、Day 13 静态检查、LLM tool schema 生成都依赖它。

## 第四章 · 作用域（Scope）

### 4.1 LEGB 规则

Python 查找变量名的顺序：

| 层级 | 含义 | 示例 |
|------|------|------|
| **L**ocal | 函数内部 | `def` 内赋值 |
| **E**nclosing | 外层嵌套函数 | 闭包 |
| **G**lobal | 模块顶层 | `COMPANY = "星火科技"` |
| **B**uilt-in | 内置名 | `len`, `print` |

```python
COMPANY = "星火科技"  # Global

def demo():
    prefix = "[局部]"  # Local
    def inner():
        return f"{prefix} {COMPANY}"  # E 然后 G
    return inner()
```

### 4.2 `global` 与 `nonlocal`

```python
count = 0

def increment_global():
    global count  # 声明修改模块级变量（慎用）
    count += 1

def make_counter():
    n = 0
    def inc():
        nonlocal n  # 修改外层函数的 n
        n += 1
        return n
    return inc
```

**培训建议**：优先用 **参数 + 返回值** 或 **闭包** 管理状态，少写 `global`。

### 4.3 闭包（Closure）

内部函数「记住」外层函数的局部变量：

```python
counter = make_counter()
counter()  # 1
counter()  # 2
```

Day 15 对话历史、Day 9 装饰器都建立在闭包之上。

## 第五章 · Lambda 表达式

### 5.1 语法

```python
lambda 参数: 表达式
```

等价于匿名的一行函数，**只能写表达式，不能写语句**。

### 5.2 与 `sorted` / `filter` 配合

```python
PRIORITY_RANK = {"P0": 0, "P1": 1, "P2": 2}

sorted(todos, key=lambda t: PRIORITY_RANK.get(t["priority"], 9))
list(filter(lambda t: not t["done"], todos))
```

`sparktech_todo/core.py` 的 `list_todos` 已使用 `lambda` 排序——与 Day 4 一致。

### 5.3 何时不用 lambda

逻辑超过一行、需复用时，用 `def`：

```python
def priority_key(todo: dict) -> tuple:
    return (PRIORITY_RANK.get(todo["priority"], 9), todo["id"])
```

## 第六章 · 递归入门

### 6.1 两个要素

1. **基线条件（base case）**：不再递归，直接返回  
2. **递归步**：问题缩小，调用自身  

```python
def factorial(n: int) -> int:
    if n <= 1:          # 基线
        return 1
    return n * factorial(n - 1)  # 递归步
```

### 6.2 课堂版 flatten

```python
def flatten_once(nested: list) -> list:
    result = []
    for item in nested:
        if isinstance(item, list):
            result.extend(item)
        else:
            result.append(item)
    return result
```

任意深度展开需递归；今日理解概念即可，Day 28 会处理嵌套 JSON。

### 6.3 递归风险

- 栈溢出：深度过大 → 改迭代或 `sys.setrecursionlimit`（不推荐）  
- 重复计算：斐波那契朴素递归 → Day 9 记忆化或循环

## 第八章 · 常见错误与排错

| 现象 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: sparktech_cleaners` | 未把 `code/` 加入 path | 入口脚本 `sys.path.insert(0, ...)` |
| `ImportError: attempted relative import` | 直接运行包内模块 | 用 `run_*.py` 或 `python -m` |
| 默认参数 list 共享 | `def f(x=[])` | 改 `None` + 内部创建 |
| `lambda` 里写 `if` 多行 | 语法不允许 | 改 `def` |
| 递归 `RecursionError` | 无基线或深度过大 | 检查 base case |
