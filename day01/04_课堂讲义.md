## 第一章 · 上午第一节：我们为什么要学「大模型应用开发」

### 1.1 先澄清三个常见误解

**误解一：「会 ChatGPT 就够了。」**  
会用聊天窗口不等于会开发。客户要的是：对接工单系统、引用内部 PDF、权限隔离、审计日志、私有化部署。这些都在应用层用 Python 完成。

**误解二：「一定要数学很好才能学 Transformer。」**  
本课程对数学的要求是：知道「模型吃 token、吐 token」即可。原理课用类比，时间留给能写进简历的项目。

**误解三：「零基础 70 天学不会。」**  
零基础指的是「没系统写过 Python」，不是「不能每天投入 6–8 小时」。课程每天环环相扣：今天的 `input` 就是两周后的 `requests.post` 里的 JSON 字段来源。

## 第二章 · 上午第二节：Python 开发环境搭建（逐步操作）

### 2.1 为什么选 Python 3.10+

- 类型注解更完善（Day 13）  
- 模式匹配 `match`（选修）  
- 主流框架已放弃 3.8 及以下  
- 与 PyTorch、vLLM 等生态对齐（Day 51+）  

在终端执行（后文统称「终端」，Windows 用 PowerShell 或 VS Code 集成终端）：

```bash
python3 --version
```

期望输出类似：`Python 3.12.3`。若显示 `command not found`，说明未安装或未加入 PATH。

### 2.2 Windows 安装要点

1. 打开 https://www.python.org/downloads/ 下载 **Windows installer (64-bit)**  
2. **务必勾选** 「Add python.exe to PATH」  
3. 选 「Install Now」  
4. 安装后**重新打开**终端，再执行 `python --version`  

旁白：没勾 PATH 是培训班第一天最高频问题。解决办法：卸载重装勾选，或手动把 `C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\` 加入环境变量。

乱码预防（可选）：

```powershell
chcp 65001
```

VS Code 设置：`"terminal.integrated.defaultProfile.windows": "PowerShell"`，文件编码 UTF-8。

### 2.3 macOS 安装要点

推荐 Homebrew：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install python@3.12
python3 --version
```

Apple Silicon 若 `python3` 指向系统旧版本，把 brew 提示的 PATH 配置写入 `~/.zshrc`。

### 2.4 Linux（Ubuntu/Debian）安装要点

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv
python3 --version
```

企业内网机器可能无法访问外网——与客户现场一致，要提前准备离线安装包或使用内网镜像源（Day 56 Docker 会再讲）。

### 2.5 VS Code 配置清单

| 步骤 | 操作 |
|------|------|
| 1 | 安装 VS Code |
| 2 | 扩展市场安装 **Python**（Microsoft） |
| 3 | 扩展市场安装 **Chinese (Simplified)**（可选） |
| 4 | `File → Open Folder` 打开你的学习目录 |

**调试配置**：第一次 F5 选 「Python File」，会生成 `.vscode/launch.json`，保留即可。

### 2.6 pip 与国内镜像（必做）

大模型开发会装大量包，国内直连 PyPI 很慢。在用户目录创建 pip 配置：

**Linux / macOS**：`~/.pip/pip.conf`  
**Windows**：`%APPDATA%\pip\pip.ini`

```ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
trusted-host = pypi.tuna.tsinghua.edu.cn
```

验证：

```bash
python3 -m pip --version
```

旁白：客户内网常有私有 PyPI（Nexus/Artifactory），格式一样，只换 URL。

## 第三章 · 下午第一节：变量、数据类型与输入输出

### 3.1 变量是什么

变量是**贴在内存数据上的标签**。Python 不需要写 `int x = 1`，直接：

```python
name = "陈晓"
```

旁白：以后读 API 文档里的 `messages: List[Dict]`，本质就是「标签指向列表，列表里装着字典」——Day 5 当天你会亲手写。

### 3.2 四种今日必会类型

| 类型 | 示例 | 典型用途 | 易错点 |
|------|------|----------|--------|
| `int` | `42` | 计数、token 数 | 除法 `/` 得 float |
| `float` | `3.14` | 温度参数、价格 | 精度问题（财务用 Decimal） |
| `str` | `"星火"` | 姓名、Prompt、JSON 片段 | 引号配对 |
| `bool` | `True` / `False` | 开关、是否住宿 | 别写 `true` 小写 |

查看类型：

```python
type(name)  # <class 'str'>
```

### 3.3 print 详解

```python
print("A", "B", sep="-", end="!\n")
# A-B!
```

- `sep`：多个参数之间的分隔符，默认空格  
- `end`：结尾字符，默认换行 `\n`  

格式化三种方式（今日掌握 f-string 即可，Day 2 深入）：

```python
employee_id = "ST-2026-001"
print(f"工号：{employee_id}")      # 推荐
print("工号：{}".format(employee_id))
print("工号：%s" % employee_id)    # 旧式，了解即可
```

**与大模型开发的联系**：Prompt 模板几乎都是 f-string 或框架里的 template：

```python
user_question = "RAG 是什么？"
prompt = f"请用三句话向零基础同事解释：{user_question}"
```

### 3.4 input 详解

```python
name = input("请输入姓名：")
```

- 返回值**永远是 str**  
- 用户直接回车会得到 `""`  
- 提示语会原样显示，不要泄露敏感信息  

布尔输入转换（信息卡片必用）：

```python
raw = input("是否住宿？(y/n)：").strip().lower()
need_dorm = raw in ("y", "yes", "是")
```

旁白：`.strip().lower()` 是 Day 2 字符串正式课的内容，今天先「拿来用」，知道是在**清洗用户输入**。

### 3.5 常量与命名规范

全大写表示「业务上不应被改掉」的配置：

```python
COMPANY_NAME = "星火科技"
CARD_WIDTH = 50
```

变量名：

- 用小写 + 下划线：`employee_id` ✅  
- 避免 `a`, `b`（除循环变量）  
- 不用拼音：`xingming` ❌  

### 3.6 注释怎么写才像工程师

```python
# 单行注释：解释下一行「为什么」

"""
多行字符串：可作模块说明（文件顶部）
"""
```

差注释：`# 打印`（废话）  
好注释：`# PRD AC-04：布尔字段展示为「是/否」而非 True/False`

### 4.6 常见报错与排查

| 报错 | 原因 | 解决 |
|------|------|------|
| `SyntaxError: invalid syntax` | 中文标点、漏冒号 | 检查第 N 行附近 |

## 第五章 · 晚自习：Git 与 GitHub（交付物的归宿）

### 5.1 为什么第一天就要 Git

张工原话：「简历上的项目，面试官会点进 GitHub 看 commit 是不是你自己一点点写的。」

### 5.2 最小工作流

```bash
cd ~/sparktech-training   # 你的根目录
git init
git config user.name "你的姓名"
git config user.email "你的邮箱"

# 创建 .gitignore 见 code/.gitignore.example
cp day01/code/.gitignore.example .gitignore

git add day01/
git commit -m "feat(day01): 入职信息卡片与学习环境初始化"
```

GitHub 新建仓库后：

```bash
git remote add origin git@github.com:你的用户名/sparktech-training.git
git branch -M main
git push -u origin main
```

### 5.3 commit message Convention（部门规范）

```
<type>(<scope>): <subject>

type: feat | fix | docs | chore
scope: day01, day12, project1 ...
```

示例：`feat(day01): 完成个人信息卡片 v1`

### 5.4 .gitignore 必忽略项

- `__pycache__/`  
- `.venv/`  
- `.env`（**永远不要提交 API Key**，Day 13 详解）  
- `.vscode/`（可选，团队统一则可提交）
