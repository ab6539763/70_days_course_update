## 1. 装饰器执行顺序详解

```python
@dec_a
@dec_b
@dec_c
def f():
    pass
```

等价于 `f = dec_a(dec_b(dec_c(f)))`。

**离函数最近的最先包装**（`dec_c` 最内层）。

调用时：**最外层 `dec_a` 的 wrapper 最先执行**。

### 1.1 retry 与 timeout 组合

| 写法 | 行为 |
|------|------|
| `@timeout` 外，`@retry` 内 | 每次重试独立超时 ✅ 推荐 |
| `@retry` 外，`@timeout` 内 | 整个重试过程共享一个超时预算 |

## 2. 闭包陷阱（装饰器带状态）

```python
def make_handlers():
    return [lambda i=i: i for i in range(3)]  # ✅ 默认参数绑定
```

错误写法 `lambda: i` 会全部捕获最终 `i=2`。

`retry` 装饰器里的 `wait = delay` 必须在 **每次装饰时** 复制，不能放在模块级可变对象。

## 3. 类方法与静态方法装饰器

```python
class API:
    @classmethod
    def from_env(cls) -> "API":
        ...

    @staticmethod
    def validate_key(key: str) -> bool:
        return key.startswith("sk-")
```

`@retry` 可用于 **模块级函数**；装饰实例方法时注意 `self` 在 `args[0]`。

## 4. functools.lru_cache vs 自定义 memoize

标准库：

```python
@functools.lru_cache(maxsize=128)
def fib(n: int) -> int:
    ...
```

- 线程安全（3.8+）  
- 只支持 hashable 参数  
- `cache_clear()` 可失效  

作业 `memoize` 是教学简化版。

## 5. asyncio 深入边界

### 5.1 何时不用 asyncio

- 脚本串行调一次 LLM → 同步 + `@retry` 足够  
- CPU 密集计算 → `multiprocessing`，不是 asyncio  

### 5.2 Task 与 Future

```python
task = asyncio.create_task(coro())
await task
```

`create_task` 立即调度；`await` 等待结果。

### 5.3 与 Day 20 httpx 衔接

```python
async with httpx.AsyncClient(timeout=20) as client:
    resp = await client.post(url, json=payload)
```

原生 async HTTP 不再需要 `to_thread`。

## 6. 生成器进阶：send 与 throw

```python
gen = echo_with_multiplier()
next(gen)
gen.send(2.0)   # 注入值
gen.throw(ValueError)  # 向生成器抛异常
```

LLM 流式场景较少用 `send`；了解即可。

## 7. typing 进阶

### 7.1 ParamSpec（装饰器类型）

课程 `api_decorators.py` 已使用：

```python
P = ParamSpec("P")
R = TypeVar("R")
def retry(...) -> Callable[[Callable[P, R]], Callable[P, R]]: ...
```

保证装饰后函数签名与原来一致。

### 7.2 NotRequired（Python 3.11+）

```python
class ChatMessage(TypedDict, total=False):
    role: Literal["user", "assistant"]
    content: str
    name: str  # 可选
```
