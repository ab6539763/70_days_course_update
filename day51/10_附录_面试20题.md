## 基础概念（1–6）

**1. 什么是 SFT？与预训练有何区别？**  
答：SFT（Supervised Fine-Tuning）在基座权重上用标注数据继续训练；预训练学通用语言，SFT 学任务分布。星火智服用 SFT 统一客服话术。

**2. LoRA 相比全量微调的核心优势？**  
答：只训练低秩适配器，可训参数 <1%，24GB 单卡可训 7B；基座冻结降低灾难性遗忘风险。

**3. RAG 能解决什么问题，不能解决什么？**  
答：能更新知识、提供 citation；不能稳定改变输出风格与敬语结构，后者需 SFT。

**4. 什么是 Hybrid 架构？**  
答：RAG 检索事实 + LoRA 模型组织语言；适用于「产品规格常更新 + 品牌语气固定」。

**5. Prompt 工程何时仍是首选？**  
答：零训练、快速迭代；高复杂度偶发推理；或流量 <5% 的 fallback。

**6. QLoRA 是什么？**  
答：4bit 量化基座 + LoRA 训练，进一步降低显存，适合运维只批 24GB 的场景。

## 场景设计（7–12）

**7. 「退款政策每周改」怎么选型？**  
答：RAG；知识可变不宜烙进权重。引用 `compare_approaches` 中「退款政策咨询 → rag」。

**8. 「统一致歉信语气」怎么选型？**  
答：SFT + LoRA；`style_fixed=True` 且无 citation 需求。

**9. 为何不能把金额数字写进微调数据？**  
答：金额随业务系统变，应 RAG/API 查事实，模型只输出流程话术，避免幻觉。

**10. DPO/RLHF 本周为何不做？**  
答：Phase4 降本 OKR 优先 SFT；偏好对齐成本高，Day 55 先用规则+LLM judge 评估。

**11. 如何向 CTO 解释「不是不用 RAG」？**  
答：RAG 查政策，LoRA 写话术；分工明确，API 费用降、一致性升。

**12. `finetune_decision_tree.py` 默认兜底是什么？**  
答：`prompt`；特征不足时不贸然微调。

**14. 「产品规格+品牌语气」为何是 hybrid？**

## 开放题（18–20）

**18. 月 API ¥128,000 如何降到目标？**  
答：80–90% 流量私有化 7B+LoRA；复杂 case 保留大模型 API；RAG 减长 prompt。

**19. 话术一致性 71%→90% 如何量化？**  
答：人工抽检 + Day 55 自动评估（风格分、关键词命中率、LLM judge）。

**20. 若 PM 坚持「全部微调」你如何说服？**  
答：用 FAQ 变更频率、合规 citation、算力成本三维度；演示决策树输出。

## 反问面试官 3 题（展示深度）

1. 贵司可变知识与固定风格的比例大约多少？决定 Hybrid 权重。  
2. 是否已有 RAG 基建可复用？星火智服答案是 Project2。  
3. 微调评估除 loss 外，业务方认什么指标？引导到 Day 55 golden set。  

## 常见错误回答（避雷）

- ❌「微调万能，所有场景都 SFT」—— 忽略 FAQ 变更与 citation。  
- ❌「RAG 过时了」—— Phase4 明确 Hybrid。  
- ❌「7B 一定比 API 便宜」—— 需算吞吐、人力、fallback 比例。
