## 第一章 · 为什么需要继承（09:00–09:45）

### 1.1 从重复代码说起

假设没有继承，OpenAI 和千问各写一套：

```python
class OpenAIModel:
    def __init__(self, model_name, api_key, temperature=0.7):
        self._model_name = model_name
        self._api_key = api_key
        self._temperature = temperature
        self._call_count = 0

    def generate(self, prompt):
        ...


class QwenModel:
    def __init__(self, model_name, api_key, temperature=0.7):
        self._model_name = model_name      # 重复
        self._api_key = api_key            # 重复
        self._temperature = temperature    # 重复
        self._call_count = 0               # 重复

    def generate(self, prompt):
        ...
```

问题一目了然：

| 问题 | 后果 |
|------|------|
| 字段赋值重复 | 改 `max_tokens` 要改 N 个类 |
| 校验逻辑重复 | `prompt.strip()` 每处抄一遍 |
| 业务无法统一调度 | 函数参数没法写成 `model: BaseModel` |

**继承**的做法：把公共部分抽到父类 `BaseModel`，子类只写差异。

### 1.2 继承语法

```python
class BaseModel:
    vendor = "unknown"

    def __init__(self, model_name: str, *, api_key: str = "", temperature: float = 0.7):
        self._model_name = model_name
        self._api_key = api_key
        self._temperature = temperature


class OpenAIModel(BaseModel):
    vendor = "openai"

    def __init__(self, model_name: str = "gpt-4o", **kwargs):
        super().__init__(model_name, **kwargs)
        self._base_url = "https://api.openai.com/v1"
```

要点：

1. `class 子类(父类):` —— 括号内写父类名  
2. 子类 **自动拥有** 父类定义的属性和方法（除非被重写）  
3. 子类可 **新增** 自己的属性（如 `_base_url`）  
4. 子类可 **覆盖** 父类方法（如 `generate`）  

▶ 打开 [code/base_model.py](./code/base_model.py) 与 [code/openai_model.py](./code/openai_model.py) 对照阅读。

### 1.3 类属性 vs 实例属性

```python
class BaseModel:
    vendor = "unknown"   # 类属性：存在类对象上，子类可覆盖

class OpenAIModel(BaseModel):
    vendor = "openai"    # 覆盖后 OpenAIModel.vendor == "openai"
```

| 种类 | 定义位置 | 典型用途 |
|------|----------|----------|
| 类属性 | `class` 体内、方法外 | `vendor` 常量、默认值 |
| 实例属性 | 通常在 `__init__` 里 `self.x =` | 每个实例独立的 `model_name`、`_api_key` |

**踩坑**：若父类 `vendor` 是可变对象（如 `list`），子类用 `vendor = []` 覆盖是安全的；但若子类写 `self.vendor.append("x")` 可能误改共享状态。今日 `vendor` 是 `str`，无此问题。

### 1.4 `is-a` 关系

面向对象里继承表达 **「是一个」**：

- `OpenAIModel` **是一个** `BaseModel`  
- `QwenModel` **是一个** `BaseModel`  

因此：

```python
m = OpenAIModel()
isinstance(m, OpenAIModel)  # True
isinstance(m, BaseModel)    # True  ← 多态的基础
```

## 第二章 · 方法重写与 super()（09:45–10:30）

### 2.1 什么是方法重写（Override）

子类定义与父类 **同名** 的方法，运行时 **子类版本优先**：

```python
class BaseModel:
    def generate(self, prompt: str):
        raise NotImplementedError("子类必须实现")


class OpenAIModel(BaseModel):
    def generate(self, prompt: str):
        return GenerationResult(text="mock openai", ...)
```

调用 `OpenAIModel().generate("hi")` 时，走子类实现，不会触发父类的 `NotImplementedError`。

这与 **重载（Overload）** 不同——Python 不支持同名不同参数类型的传统重载；后者靠默认参数、`*args` 或 `@singledispatch` 实现，今日不展开。

### 2.2 super() 做什么

子类 `__init__` 里几乎总要写：

```python
super().__init__(model_name, api_key=api_key, temperature=temperature)
```

含义：**按 MRO 顺序调用父类的 `__init__`**，避免重复写字段赋值。

在 `generate` 里复用父类钩子：

```python
def generate(self, prompt: str, **kwargs):
    prompt = super()._before_generate(prompt)  # 父类：strip + 计数
    # 子类 mock 逻辑 ...
```

**为什么不写 `BaseModel._before_generate(self, prompt)`？**

单继承时多数情况等价；但 `super()` 在 **多继承** 场景下更安全（按 MRO 链）。培训部要求养成 `super()` 习惯。

### 2.3 模板方法模式（钩子）

`BaseModel` 的设计：

| 方法 | 谁实现 | 作用 |
|------|--------|------|
| `generate` | 子类必须重写 | 核心差异：如何调 API |
| `_before_generate` | 父类实现 | 统一校验与 `call_count` |
| `build_system_prefix` | 父类默认，子类可重写 | 厂商前缀字符串 |

这是 **模板方法模式** 的雏形：父类定流程骨架，子类填具体步骤。Day 48 Agent 工具链里也会见到类似「框架定顺序、业务填节点」的结构。

### 2.4 实操：VerboseOpenAI

见 [code/magic_methods_demo.py](./code/magic_methods_demo.py)：

```python
class VerboseOpenAI(OpenAIModel, LoggingMixin):
    def generate(self, prompt, **kwargs):
        self.log("开始生成...")
        result = super().generate(prompt, **kwargs)
        self.log("完成")
        return result
```

`super().generate` 跳转到 `OpenAIModel.generate`，不会递归死循环——因为 `super()` 找的是 **MRO 中的下一个** 实现。

▶ 运行：`python3 magic_methods_demo.py`，观察第二节输出。

## 第三章 · 多态（10:30–12:00）

### 3.1 定义

**多态（Polymorphism）**：同一操作作用于不同对象，产生不同行为。

```python
def route_prompt(models: list[BaseModel], prompt: str):
    for m in models:
        out = m.generate(prompt)   # 运行时决定调哪个 generate
        print(m.vendor, out.text)
```

`models` 里既有 `OpenAIModel` 也有 `QwenModel`，但 `route_prompt` **只声明依赖 `BaseModel`**——这就是李姐要的「统一接口」。

### 3.2 编译时类型 vs 运行时类型

```python
def use(model: BaseModel):
    model.generate("hello")

use(OpenAIModel())   # 静态类型注解是 BaseModel，实际对象是 OpenAIModel
use(QwenModel())     # 同上
```

Python 是 **鸭子类型** 语言：不强制继承也能调 `generate`，但工程上 **显式继承** 能：

- 让 IDE 补全与类型检查器（mypy）生效  
- 让同事一眼看懂契约  
- 让 `NotImplementedError` 约束漏实现的子类  

### 3.3 反模式：业务层满屏 if/elif

```python
# 张工会在 Code Review 打回
def bad_generate(model, prompt):
    if type(model) is OpenAIModel:
        return call_openai(...)
    elif type(model) is QwenModel:
        return call_qwen(...)
```

应改为 **只调** `model.generate(prompt)`。`isinstance` 仅用于 **可选扩展能力**：

```python
if isinstance(model, QwenModel):
    return model.generate_with_search(prompt)
```

### 3.4 GenerationResult：统一返回结构

多态不仅体现在「不同子类」，也体现在 **返回值一致**：

```python
@dataclass
class GenerationResult:
    text: str
    model: str
    vendor: str
    prompt_tokens: int = 0
    ...
```

业务层可把多家结果放进 `list[dict]` 再 `json.dumps`，无需按厂商解析不同字段名——与 Day 5 JSON 思维一脉相承。

### 3.5 上午小结白板

```text
  继承     →  代码复用、is-a 关系
  重写     →  子类替换父类方法实现
  super()  →  复用父类逻辑，配合 MRO
  多态     →  BaseModel 引用，子类实例，运行时绑定
```

## 第四章 · 魔术方法概览（14:00–14:45）

### 4.1 什么是魔术方法

双下划线包裹的方法（如 `__init__`）由 Python **自动调用**，也称 **dunder**（double underscore）。

Day 8 已学 `__init__`；今日重点：

| 方法 | 触发时机 |
|------|----------|
| `__str__` | `print(obj)`、`str(obj)` |
| `__repr__` | 交互式回显、`repr(obj)`、容器里的默认表示 |
| `__call__` | `obj(...)` 像函数一样调用 |

### 4.2 __str__ vs __repr__

```python
m = QwenModel("qwen-plus", api_key="sk-x")

print(m)        # __str__  → 通义千问 模型 qwen-plus (temp=0.8, 已配置 Key)
print(repr(m))  # __repr__ → QwenModel(model_name='qwen-plus', temperature=0.8, max_tokens=2048)
```

经验法则（Guido 口径）：

| | 受众 | 目标 |
|---|------|------|
| `__str__` | 终端用户、运维 | 可读、简短 |
| `__repr__` | 开发者、日志 | 明确、尽量 `eval(repr(obj))` 可重建 |

**若只实现一个**：优先 `__repr__`；未定义 `__str__` 时 `str(obj)` 会回退到 `__repr__`。

`BaseModel` 两个都实现，因为星火智服既要给人看监控面板，也要给开发看调试日志。

### 4.3 __call__ 与可调用对象

```python
class BaseModel:
    def __call__(self, prompt: str, **kwargs):
        return self.generate(prompt, **kwargs)

model = OpenAIModel()
model("你好")              # 等价 model.generate("你好")
callable(model)            # True
```

意义：

1. **语法糖**：短写，贴近「模型是函数」的直觉  
2. **框架对齐**：LangChain `Runnable`、PyTorch `nn.Module` 都可 `__call__`  
3. **统一入口**：业务只写 `result = model(user_input)`  

注意：`__call__` 不应做与 `generate` 矛盾的逻辑，今日实现为 **纯委托**。

### 4.4 GenerationResult 上的魔术方法

```python
def __str__(self) -> str:
    return self.text

def __repr__(self) -> str:
    return f"GenerationResult(model={self.model!r}, vendor={self.vendor!r}, ...)"
```

`print(result)` 直接出正文；调试时 `repr` 保留元数据——**数据类也要认真写 dunder**。

## 第五章 · @property 详解（14:45–15:30）

### 5.1 为什么不用公开字段

朴素写法：

```python
model.temperature = 0.7
model._temperature = 0.7   # 约定「内部」但仍可被随意改
```

问题：`temperature = 99` 不会在赋值时报错，直到 API 调用失败。

**@property** 把「读属性」变成方法调用，可在 **读/写时插入逻辑**。

### 5.2 只读 property

```python
@property
def model_name(self) -> str:
    return self._model_name

@property
def call_count(self) -> int:
    return self._call_count
```

外部 `model.model_name` 语法像字段，实则 getter；无 setter 则 **只读**。

`is_configured` 是 **派生属性**：

```python
@property
def is_configured(self) -> bool:
    return bool(self._api_key)
```

不单独存字段，由 `_api_key` 计算——减少状态不一致。

### 5.3 带 setter 的 property

```python
@property
def temperature(self) -> float:
    return self._temperature

@temperature.setter
def temperature(self, value: float) -> None:
    if not 0.0 <= value <= 2.0:
        raise ValueError("temperature 必须在 0.0～2.0 之间")
    self._temperature = value
```

调用：

```python
model.temperature = 1.0   # OK
model.temperature = 3.0   # ValueError
```

这与 Pydantic / dataclass 校验思想一致：Day 23 学 `BaseModel`（第三方）时会发现字段约束是同一类问题。

### 5.4 计算属性示例：Rectangle

见 [code/property_demo.py](./code/property_demo.py)：

```python
@property
def area(self) -> float:
    return self.width * self.height
```

`area` 不由外部赋值，随 `width`/`height` 变化——**派生状态用 property，不用独立字段**。

### 5.5 API Key 脱敏

```python
@property
def api_key_masked(self) -> str:
    if not self._api_key:
        return "(未设置)"
    return self._api_key[:4] + "****" + self._api_key[-4:]
```

**永远不要** 实现 `api_key` 读取完整 Key 的 property 给日志用。王工审计要求：日志只能出现 masked 形式。

### 5.6 property 与私有化约定

Python 没有真正的 `private`：

| 写法 | 含义 |
|------|------|
| `name` | 公开 |
| `_name` | 约定内部使用（仍能访问） |
| `__name` | 名称改写，防子类意外覆盖（今日未用） |

配合 `@property`：外部只接触 `model_name`，内部用 `_model_name` 存储。

### 6.5 常见踩坑
