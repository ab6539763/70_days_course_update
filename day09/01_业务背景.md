## 3. 技术债：当前「脚本版」的问题

培训组上周提交的临时脚本（伪代码）：

```python
def ask_llm(prompt, vendor):
    if vendor == "openai":
        return call_openai(prompt)
    elif vendor == "qwen":
        return call_qwen(prompt)
    else:
        raise ValueError("unknown")
```

张工点评：

| 问题 | 后果 | Day 9 解法 |
|------|------|------------|
| 每增厂商改一处 `elif` | 合并冲突、漏改 | 新增子类文件即可 |
| 返回格式不统一 | 上层又要 `if` 解析 | `GenerationResult` 统一结构 |
| 配置散落全局变量 | 温度、Key 难管理 | 封装进实例 + `@property` |
| 无法 `print(model)` 调试 | 运维排查困难 | `__str__` / `__repr__` |

## 4. 与大模型开发的隐性联系

| 今日知识点 | 日后场景 |
|------------|----------|
| 继承 + 多态 | LangChain `BaseChatModel`、各厂商 Adapter |
| `super()` | 子类扩展父类校验、计数、日志 |
| `__call__` | `Runnable`、可调用模型包装器 |
| `@property` | Pydantic `BaseModel` 字段校验（Day 23 预告） |
| `__repr__` | Jupyter / 日志里看清对象状态 |
| 统一 `generate()` | OpenAI `chat.completions`、千问 `Generation.call` 抽象 |

张工补充：

> 「OpenAI SDK 的 `client.chat.completions.create` 和千问的接口长得不一样，但你的 **业务代码** 应该只认识 `model(prompt)`。今天写的类层次，就是日后接 LangChain 之前的『裸 Python 版适配层』。」
