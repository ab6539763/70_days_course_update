### 1.1 现场情况

周三上午，王工在部门协作群发了一则通知：

> 「OA 正式接口预计下月才上线。本周联调先用附件里的 **Mock 员工 API 响应**（JSON 格式）。  
> 请大模型应用开发部培训生：  
> 1. 解析 JSON，取出 `employees` 数组；  
> 2. 字段与 Day 1 入职卡片对齐；  
> 3. 调用 Day 2 清洗函数处理脏数据；  
> 4. 导出 `employees_clean.json` 供信息科导入测试库。」

张工把任务翻译成工程师语言：

| 业务说法 | 技术说法 |
|----------|----------|
| Mock API 响应 | 本地 JSON 文件模拟 HTTP body |
| 取出员工列表 | `dict` 嵌套访问 + `list` 遍历 |
| 字段对齐 | 统一 schema（key 命名与类型） |
| 洗干净再导出 | `json.dumps` 序列化清洗后的 `list[dict]` |
| 下午五点前 | 脚本可重复运行，输出路径固定 |

## 3. 与大模型开发的隐性联系

| 今日技能 | 日后场景 |
|----------|----------|
| 嵌套 `dict` 取值 | 解析 OpenAI `response["choices"][0]["message"]` |
| `json.loads` | 把 API 返回的 **字符串 body** 转成 Python 对象 |
| `json.dumps` | 构造请求体、写日志、持久化对话历史 |
| 遍历 `list[dict]` | RAG 检索结果 `documents[]` 每条含 `content` + `metadata` |
| 字段清洗后序列化 | 入库前统一 schema，避免向量库 metadata 脏数据 |

产品部李姐补充：智服后台「知识库文档列表」接口返回的也是 JSON 数组——今日练的 **解析 → 变换 → 再序列化** 是后端对接的基本功。
