# Day 19 架构与设计 · Schema / Runner / Agent 三层

## 1. 总体架构

```text
┌─────────────────────────────────────────────────────────────────────┐
│                         入口层                                        │
│              function_calling_agent.py / verify_day19.py             │
└────────────────────────────┬────────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    Agent 循环层                                       │
│   while round < max_rounds:                                            │
│     1. client.chat_with_tools(messages, tools)                       │
│     2. if tool_calls → tool_runner → append tool messages            │
│     3. else → return final_answer                                    │
└────────────┬───────────────────────────────┬──────────────────────────┘
             │                               │
             ▼                               ▼
┌────────────────────────┐    ┌────────────────────────────────────────┐
│  llm_client.py         │    │  tool_runner.py                         │
│  ToolCallingLLMClient  │    │  parse_arguments → TOOL_REGISTRY       │
│  mock / live           │    │  → ToolCallResult → tool message       │
└────────────────────────┘    └───────────────┬────────────────────────┘
                                              │
                                              ▼
                              ┌────────────────────────────────────────┐
                              │  tools.py + data/mock_products.json     │
                              │  get_weather / calculate / query_products│
                              └────────────────────────────────────────┘
                                              ▲
                              ┌───────────────┴────────────────────────┐
                              │  schemas/*.json                         │
                              │  OpenAI tools 参数（给模型看）            │
                              └────────────────────────────────────────┘
```

**设计原则**（张工规范）：

1. **Schema 与实现分离**：JSON 描述接口，Python 函数负责执行  
2. **单一注册表**：`TOOL_REGISTRY` 是 tool_runner 唯一路由来源  
3. **消息数组即状态**：Agent 不维护额外状态机，全靠 `messages` 追加  
4. **mock 可替换**：mock 与 live 分支在 `llm_client` 内隔离  

## 2. messages 数组演化

```text
Round 1 发送:
  [system, user: "北京天气怎么样？"]

Round 1 响应 (tool_calls):
  [..., assistant: {tool_calls: [{get_weather, {city:"北京"}}]}]

Round 2 发送（追加 tool 结果）:
  [..., tool: {tool_call_id, name, content: "{...json...}"}]

Round 2 响应 (final):
  [..., assistant: {content: "北京当前晴，28°C..."}]
```

| role | 何时出现 | 关键字段 |
|------|----------|----------|
| system | 对话开始 | content |
| user | 用户输入 | content |
| assistant | 模型回复 | content 和/或 tool_calls |
| tool | 工具执行后 | tool_call_id, name, content |

## 3. tool_call 数据结构

```json
{
  "id": "call_abc123",
  "type": "function",
  "function": {
    "name": "get_weather",
    "arguments": "{\"city\": \"北京\"}"
  }
}
```

**注意**：`arguments` 是 **JSON 字符串**，不是对象——`tool_runner` 负责 `json.loads`。

## 4. calculate 安全设计

```text
expression 字符串
      │
      ▼
ast.parse(mode="eval")
      │
      ▼
仅允许 Constant / BinOp / UnaryOp
      │
      ▼
拒绝 Name / Call / Attribute 等节点
```

| 允许 | 禁止 |
|------|------|
| `+ - * / // % **` | `eval()` 直接执行 |
| 括号嵌套 | 字母变量、函数调用 |
| 浮点字面量 | `import os` 等 |

## 5. mock 模式设计

```text
用户文本
    │
    ▼
启发式规则（关键词 + 正则）
    │
    ├─ 命中天气/计算/产品 → 构造 tool_calls
    │
    └─ 上一条是 tool 消息 → 拼最终自然语言
```

mock 不发起 HTTP，但 **循环结构与 live 完全一致**，便于教学与 CI。

## 7. 与 OpenAI SDK 对照

| 手写（本日） | OpenAI SDK |
|--------------|------------|
| `chat_with_tools(...)` | `client.chat.completions.create(tools=...)` |

| `role=tool` 消息 | 同 |
| Agent while 循环 | 需自己写（或使用 Assistants API） |
