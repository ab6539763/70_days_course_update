# Day 19 课堂讲义 · Function Calling 与手写 Agent 循环

> **旁白**：昨天你们的助手只会聊天；今天让它 **能查数据、能算数**。关键认知：**LLM 是调度员，不是数据库**。

---

## 第一章 · Function Calling 原理（09:00–10:00）

### 1.1 为什么需要工具

| 场景 | 纯 LLM | + 工具 |
|------|--------|--------|
| 北京天气 | 可能瞎编 | `get_weather("北京")` 返回真值 |
| `(12+8)*3` | 可能算错 | `calculate` 精确计算 |
| 库存查询 | 幻觉 SKU | `query_products` 查库 |

### 1.2 四步循环

```text
1. 把 tools schema 发给模型
2. 模型返回 tool_calls（或最终文本）
3. 执行工具，得到结果
4. 把结果作为 role=tool 消息塞回，goto 2
```

### 1.3 OpenAI tools 参数

```python
payload = {
    "model": "gpt-4o-mini",
    "messages": [...],
    "tools": load_all_schemas(),   # JSON Schema 数组
    "tool_choice": "auto",         # 模型决定是否调用
}
```

打开 [code/schemas/weather.json](./code/schemas/weather.json) 对照字段。

**讲师强调**：`description` 写清楚，模型才知道何时调用。

## 第二章 · JSON Schema 编写（10:00–11:00）

### 2.1 结构模板

```json
{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "查询城市天气",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {"type": "string", "description": "城市名"}
      },
      "required": ["city"]
    }
  }
}
```

### 2.2 三工具分工

| 工具 | 类型 | 数据源 |
|------|------|--------|
| get_weather | 外部 API 模拟 | MOCK_WEATHER 字典 |
| calculate | 计算 | AST 安全 eval |
| query_products | DB 查询 | mock_products.json |

▶ 运行：`python3 tools.py`

## 第三章 · tool_runner 执行层（14:00–14:45）

### 3.1 解析 arguments

```python
args = json.loads(tool_call["function"]["arguments"])
output = TOOL_REGISTRY[name](**args)
```

### 3.2 生成 tool 消息

```python
{
    "role": "tool",
    "tool_call_id": "call_abc123",  # 必须与 tool_call.id 对应
    "name": "get_weather",
    "content": '{"city":"北京","temperature":28,...}'
}
```

**讲师强调**：`tool_call_id` 对不上，模型会懵。

▶ 运行：`python3 tool_runner.py`

## 第四章 · Agent 循环（14:45–16:30）

### 4.1 核心代码结构

```python
for round_idx in range(1, max_rounds + 1):
    result = client.chat_with_tools(messages, tools)
    messages.append(build_assistant_message(result))

    if not result.message.has_tool_calls:
        return result.message.content

    report = run_tool_calls(result.message.tool_calls)
    messages.extend(report.tool_messages)
```

打开 [code/function_calling_agent.py](./code/function_calling_agent.py) 对照完整实现。

### 4.2 多工具场景

用户：「上海天气如何，顺便算 2 的 10 次方」

mock 模式可能一次返回 **两个** tool_call：
- `get_weather(city="上海")`
- `calculate(expression="2**10")`

### 4.3 max_rounds 防死循环

若模型反复调工具不给出答案，超过 `max_rounds` 应优雅退出。

▶ 运行：`python3 function_calling_agent.py`

## 第六章 · 验收与排错（17:00–17:30）

### 6.1 常见错误

| 现象 | 原因 |
|------|------|
| 模型不调工具 | description 不清；temperature 太高 |
| arguments 解析失败 | 模型返回非 JSON 字符串 |
| tool 消息无响应 | 缺少 tool_call_id |
| 循环不结束 | 未判断 `has_tool_calls` |


## 今日小结

| 概念 | 一句话 |
|------|--------|
| tools schema | 告诉模型「有哪些函数、参数长什么样」 |
| tool_calls | 模型的「调用意图」，不是执行结果 |
| tool_runner | 把意图变成真结果 |
| Agent 循环 | 反复对话直到模型说出最终答案 |
