## 必做 B · Pydantic 实验

### B1 空白 message

- HTTP **422 Unprocessable Entity**  
- `detail` 为数组，含 `loc: ["body", "message"]`  
- `msg` 含「不能为空白」或 `string_too_short`（取决于校验顺序）

### B2 tools_used 默认值

- 类型：`list[str]`  
- `Field(default_factory=list)` → 省略时序列化为 `"tools_used": []`  
- 响应合法，OpenAPI 中该字段非 required

### B3 为何用 field_validator

- **单一真相源**：无论 curl、`/docs`、TestClient 都走同一校验  
- **可测试**：`verify_day23.py` 直接测 `ChatRequest` 不经过 HTTP  
- 路由层 `strip()` 容易遗漏其他入口（如未来 WebSocket）

## 必做 C · GET /api/tools

```python
from chat_service import ChatService

# 在 main.py 顶部已有 chat_service 实例

@app.get("/api/tools", response_model=list[str], tags=["Chat"])
def list_tools() -> list[str]:
    return chat_service._tools.list_tools()
```

更干净的做法是在 `ChatService` 增加公开方法：

```python
# chat_service.py
def list_tool_names(self) -> list[str]:
    return self._tools.list_tools()

# main.py
@app.get("/api/tools", response_model=list[str], tags=["Chat"])
def list_tools() -> list[str]:
    return chat_service.list_tool_names()
```

预期响应：`["calc", "get_weather", "lookup_order"]`（字母序）。

## 选做 D · Day 22 联调

**常见 CORS 报错**：

```text
Access to fetch at 'http://127.0.0.1:8000/api/chat' from origin 'http://127.0.0.1:8080'
has been blocked by CORS policy
```

**解决**：确认 `main.py` 已 `add_middleware(CORSMiddleware, ...)`，重启 uvicorn。

**Network 检查点**：

| 项 | 预期 |
|----|------|
| Request URL | `http://127.0.0.1:8000/api/chat` |
| Method | POST |
| Status | 200 |
| Response `reply` | 非空字符串 |

## 选做 E · live 模式

| 维度 | mock | live |
|------|------|------|
| 工具场景 | 关键词确定性回复 | 可能更自然，仍可能调工具（若接 Function Calling） |
| 兜底回复 | 固定提示文案 | 模型自由发挥 |
| 成本 | 无 | 消耗 token |
| CI | 适用 | 需 Key，一般不跑 |

## 选做 F · OpenAPI

`openapi.json` 中 `paths` 应含：

- `/`  
- `/health`  
- `/items/{item_id}`  
- `/api/chat`  
- `/sessions/{session_id}/messages`  
- `/sessions/{session_id}`  

`ChatRequest` 的 `required` 通常仅 `["message"]`；`session_id`、`stream` 有默认值故非 required。
