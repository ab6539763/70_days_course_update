## 第二章 · 高频错题讲评（09:15–10:00）

### 2.1 多轮上下文截断（Day 15）

**误区**：`messages` 无限 append，迟早超 token 上限。

**正解**：保留 `system` + 最近 N 条：

```python
def trim(self, max_messages: int = 20) -> None:
    system = [m for m in self._messages if m["role"] == "system"]
    rest = [m for m in self._messages if m["role"] != "system"]
    self._messages = system + rest[-max_messages:]
```

### 2.2 temperature 语义（Day 16）

| 值 | 行为 | 场景 |
|----|------|------|
| 0 | 近乎确定性 | 分类、JSON 抽取 |
| 0.7 | 平衡 | 通用对话 |
| 1.0+ | 更随机 | 创意写作 |

**考点**：回归测试用 `temperature=0`，创意文案用 `0.8+`。

### 2.3 Prompt 四要素（Day 17）

1. **角色**（你是谁）  
2. **任务**（要做什么）  
3. **约束**（格式、长度、禁止项）  
4. **示例**（few-shot）

综合助手的 `SYSTEM_PROMPT` 必须写明 **可用工具列表**，否则模型不知道何时调用工具。

### 2.4 JSON Mode（Day 18）

`response_format={"type": "json_object"}` 要求 Prompt 里出现 “JSON” 字样，且模型只输出 JSON。

今日工具返回用 `json.dumps(..., ensure_ascii=False)` 保证中文可读。

### 2.5 Function Calling 环（Day 19）

```text
用户输入 → 模型（带 tools schema）→ tool_calls?
    ├─ 否 → 直接 assistant 回复
    └─ 是 → 执行工具 → 结果写入 messages → 再调模型 → 最终回复
```

**考点**：`tool_calls` 是模型输出的一部分，不是用户输入。

### 2.6 流式 SSE（Day 20）

HTTP 响应头：`Content-Type: text/event-stream`

单行格式：`data: {"choices":[{"delta":{"content":"你"}}]}\n\n`

终端流式用生成器等价实现，无需 HTTP：

```python
def stream_tokens(text: str, *, chunk_size: int = 2):
    for i in range(0, len(text), chunk_size):
        yield text[i : i + chunk_size]
```

### 3.1 工具环核心逻辑

```python
for round_idx in range(MAX_TOOL_ROUNDS):
    tool_call = self.tools.maybe_invoke(user_text)  # mock 路由
    if tool_call is None:
        break
    result = self.tools.execute(tool_call.name, tool_call.arguments)
    self.session.add_tool_result(tool_call.name, result)
# 然后生成最终 assistant 回复（流式或整段）
```

### 3.2 流式打印

```python
if self.stream_enabled:
    print("\n助手> ", end="", flush=True)
    full = ""
    for chunk in self.client.stream_chat(messages):
        print(chunk, end="", flush=True)
        full += chunk
    print("\n")
    self.session.add_assistant_message(full)
```

**讲师强调**：`flush=True` 否则终端可能缓冲，看不到「打字机」效果。
