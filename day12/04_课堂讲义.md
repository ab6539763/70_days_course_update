## 第一章 · HTTP 基础（09:00–10:30）

### 1.1 什么是 HTTP

**HTTP**（HyperText Transfer Protocol）是客户端与服务器之间的请求-响应协议。

```text
  客户端（你的 Python 脚本）          服务器（DeepSeek / httpbin）
         │                                    │
         │  ──── HTTP Request ────────────▶   │
         │       方法 URL 头 体               │
         │                                    │
         │  ◀─── HTTP Response ───────────   │
         │       状态码 头 体                 │
```

星火智服链路：

```text
  cli_chat_v0.py  →  LLMClient  →  requests  →  DeepSeek API  →  JSON 回复
```

### 1.2 GET vs POST

| 方法 | 典型用途 | 参数位置 | LLM 场景 |
|------|----------|----------|----------|
| **GET** | 获取资源 | URL 查询字符串 `?key=value` | 不用（prompt 太长） |
| **POST** | 提交数据 | 请求体 body | **Chat Completions** |

```python
# GET — 参数在 URL
requests.get("https://httpbin.org/get", params={"day": 12})

# POST — 数据在 body（LLM API 同款）
requests.post(url, headers=headers, json=payload)
```

> **讲师强调**：`json=payload` 会自动设置 `Content-Type: application/json` 并把 dict 序列化为 JSON 字符串。

### 1.3 状态码（Status Code）

| 范围 | 含义 | 调 API 时 |
|------|------|-----------|
| **2xx** | 成功 | `200 OK`，`response.ok == True` |
| **4xx** | 客户端错误 | `401` Key 错；`429` 限流 |
| **5xx** | 服务端错误 | 厂商故障，可重试 |

```python
response = requests.get(url)
print(response.status_code)  # 200
print(response.ok)           # True（仅 2xx）
```

### 1.4 Headers（请求头）

常见头：

| Header | 作用 |
|--------|------|
| `Content-Type` | body 格式，JSON 为 `application/json` |
| `Authorization` | 鉴权，`Bearer <API_KEY>` |
| `User-Agent` | 客户端标识（可选） |

LLM API 必备：

```python
headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}
```

### 1.5 Body（请求体）

POST 的 body 是一段字节流；API 场景下通常是 **JSON 文本**：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {"role": "user", "content": "你好"}
  ]
}
```

Day 5 学的 `json.dumps(dict)` → 就是 body 的内容。

## 第二章 · requests 库实战（10:30–12:00）

### 2.1 安装与导入

Day 10 已在 `requirements.txt` 声明：

```bash
pip install -r requirements.txt
```

```python
import requests

response = requests.get("https://httpbin.org/get", timeout=15)
```

**`timeout`**：防止网络挂死，生产必设。

### 2.2 读取响应

```python
response.status_code          # int
response.headers              # 响应头 dict-like
response.text                 # 原始字符串 body
response.json()               # 解析 JSON → dict（LLM 用这个）
```

### 2.3 POST JSON 完整示例

打开 [code/http_basics_demo.py](./code/http_basics_demo.py) 第二节：

```python
payload = {
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "你好，星火智服！"}],
}
response = requests.post(
    url,
    headers={"Content-Type": "application/json"},
    json=payload,
    timeout=15,
)
data = response.json()
print(data["json"])  # httpbin 回显你发的 JSON
```

**对照下午**：把 URL 换成 `https://api.deepseek.com/v1/chat/completions`，加上 `Authorization`，`data["json"]` 换成 `data["choices"][0]["message"]["content"]`。

### 2.4 异常处理（预习）

```python
try:
    response = requests.post(url, json=payload, timeout=60)
    response.raise_for_status()  # 4xx/5xx 抛 HTTPError
except requests.RequestException as exc:
    print(f"请求失败: {exc}")
```

今日 `LLMClient` 用显式 `status_code` 判断，便于给出中文业务错误。

## 第三章 · LLM API 核心概念（14:00–15:00）

### 3.1 API Key

- 厂商控制台申请，形如 `sk-xxxxxxxx`  
- **身份凭证**，等同密码  
- 通过 `Authorization: Bearer <key>` 发送  
- **只放环境变量或密钥管理服务**，绝不写进代码、不进 Git  

```bash
# .env（本地，不入库）
DEEPSEEK_API_KEY=sk-your-key-here
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

```python
from dotenv import load_dotenv
load_dotenv()
import os
api_key = os.getenv("DEEPSEEK_API_KEY", "")
```

### 3.2 messages 格式

OpenAI 兼容 Chat API 用 **消息列表** 表示对话：

| role | 含义 |
|------|------|
| `system` | 系统提示，定义 AI 人设与规则 |
| `user` | 用户输入 |
| `assistant` | 模型历史回复（Day 14 多轮时追加） |

```python
messages = [
    {"role": "system", "content": "你是星火智服客服助手。"},
    {"role": "user", "content": "打印机驱动在哪下载？"},
]
```

### 3.3 请求 payload

```python
payload = {
    "model": "deepseek-chat",
    "messages": messages,
    "temperature": 0.7,   # 随机性，0~2，越低越稳定
    "max_tokens": 1024,   # 回复最大 token 数
}
```

### 3.4 解析响应

```python
data = response.json()
content = data["choices"][0]["message"]["content"]
usage = data.get("usage", {})
print(usage["total_tokens"])  # 计费与监控
```

**防御式解析**（今日 `LLMClient` 已实现）：

```python
try:
    content = data["choices"][0]["message"]["content"]
except (KeyError, IndexError, TypeError):
    raise LLMClientError("无法解析响应结构")
```

### 4.2 mock 模式

无 `DEEPSEEK_API_KEY` 时：

1. `mock_mode == True`  
2. 打印 `POST` URL、脱敏 headers、完整 JSON body  
3. 返回带 `[MOCK 回复]` 前缀的文本  

**价值**：无 Key 的学员、CI 流水线、Code Review 均可运行。

### 4.3 LIVE 模式

有 Key 时：

```python
response = requests.post(
    f"{base_url}/v1/chat/completions",
    headers={"Authorization": f"Bearer {api_key}", ...},
    json=payload,
    timeout=60,
)
```

| status | 处理 |
|--------|------|
| 200 | 解析 `choices[0].message.content` |
| 401 | `LLMClientError("API Key 无效")` |
| 429 | 限流提示 |

## 第六章 · 安全与排错

### 6.1 安全红线

| ❌ 禁止 | ✅ 正确 |
|---------|---------|
| `api_key = "sk-abc..."` 写死在 .py | `os.getenv("DEEPSEEK_API_KEY")` |
| 把 `.env` 提交 Git | `.gitignore` + 只提交 `.env.example` |
| 日志打印完整 Key | 前 4 位 + `****` |

### 6.2 常见问题

| 现象 | 排查 |
|------|------|
| 一直 MOCK | 检查 `.env` 是否在 `code/` 目录、`load_dotenv()` 是否执行 |
| 401 | Key 错误或过期，重新申请 |
| 连接超时 | 网络/代理；调大 `timeout` |
| `JSONDecodeError` | 响应非 JSON，打印 `response.text` |
| httpbin 失败 | 课堂可跳过上午 demo，下午 mock 不依赖外网 |

### 6.3 自检三问（业务背景引用）

1. **为何 POST？** — prompt 与 messages 体积大、含敏感信息，不应出现在 URL。  
2. **Key 进 Git？** — 泄露即资损，需轮换 Key 并审计提交历史。  
3. **mock 价值？** — 可测试、可 Review、可演示，与 LIVE 同接口。
