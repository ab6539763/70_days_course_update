## 1. 目标

提供命令行待办管理工具，在**内存**中用 `list` 存储任务，支持增删改查与状态切换，作为 Sprint 规划会前的内部任务跟踪原型，并为后续 JSON 持久化与 Agent 任务列表奠定数据结构。

## 2. 用户故事

| ID | 角色 | 故事 | 优先级 |
|----|------|------|--------|
| US-01 | 李姐 | 快速添加一条待办并看到自增编号 | P0 |
| US-02 | 李姐 | 列出全部待办，区分已完成/未完成 | P0 |
| US-03 | 培训生 | 将指定编号标记为已完成 | P0 |
| US-04 | 张工 | 删除错误或重复的待办 | P0 |
| US-05 | 培训生 | 按优先级或创建顺序查看列表 | P1 |
| US-06 | 张工 | 核心逻辑与 CLI 分离，便于 Day 6 函数重构 | P1 |

## 3. 数据模型（v1.0）

每条待办为 **dict**（Day 5 将系统学习 dict，今日先按字段使用）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 自增，从 1 开始 |
| `title` | str | 任务标题，经 `strip` 后非空 |
| `done` | bool | `False` 未完成，`True` 已完成 |
| `priority` | str | `P0` / `P1` / `P2`，默认 `P1` |
| `tags` | list[str] | 标签列表，可用 set 去重后存回 |

全局状态：

```python
todos: list[dict] = []      # 主存储
next_id: int = 1            # 下一个可用 id
```

## 4. 功能需求

### 4.1 命令（CLI 菜单）

| 编号 | 命令 | 行为 |
|------|------|------|
| 1 | add | 输入标题、可选优先级与标签，追加到 `todos` |
| 2 | list | 展示全部；支持子选项：全部 / 仅未完成 / 仅已完成 |
| 3 | complete | 输入 id，将对应项 `done` 置为 `True` |
| 4 | delete | 输入 id，从列表中移除该项 |
| 5 | stats | 显示总数、完成数、完成率（选做见作业） |
| 0 | quit | 退出并提示「数据未持久化」 |

### 4.2 列表展示格式（f-string）

```text
[#1] [ ] P1 | 补全接口文档 | tags: api,doc
[#2] [x] P0 | 验收登录流程 | tags: qa
```

- `[ ]` 未完成，`[x]` 已完成  
- 列表默认按 `id` 升序；可选按 `priority` 排序（P0 在前）  

### 4.3 校验规则

| 编号 | 规则 |
|------|------|
| V-01 | 标题 strip 后不得为空 |
| V-02 | complete/delete 时 id 必须存在，否则友好报错 |
| V-03 | 优先级只能是 P0/P1/P2，非法则回退 P1 |
| V-04 | 标签逗号分隔，去重、去空（可用 set） |

### 4.4 教学演示模块

| 文件 | 内容 |
|------|------|
| `list_demo.py` | CRUD、切片、sort/sorted、列表推导式 |
| `tuple_set_demo.py` | 元组打包解包、集合去重与交并差 |

## 5. 非功能需求

- Python 3.10+，标准库；内存存储，**不要求**文件读写（Day 5 作业）  
- 单入口：`python3 todo_manager.py`  
- 核心函数带类型注解与 docstring  
- 代码含中文注释，说明与 Day 48 的衔接点  

## 6. 验收标准

| 编号 | 条件 |
|------|------|
| AC-01 | add 后 list 可见新任务，id 连续自增 |
| AC-02 | complete 后状态变为 `[x]`，任务仍在列表中 |
| AC-03 | delete 后该 id 不再出现 |
| AC-04 | 空标题被拒绝并提示 |
| AC-05 | 非法 id 操作不崩溃，打印明确错误信息 |
| AC-06 | `list_demo.py`、`tuple_set_demo.py` 可独立运行 |
