## 1. 目标

1. **统一命名空间**：将分散逻辑收敛到 `sparktech/` 单包，含 `exceptions.py` 与 `utils/` 子包。  
2. **异常工程化**：业务错误通过自定义异常抛出，禁止静默 `print` 后 `return None`。  
3. **环境可复现**：提供 `requirements.txt` 与 `setup_venv.sh`，新人三步可运行。  
4. **教学完整**：`demo_imports.py`、`demo_exceptions.py` 覆盖当日全部语法点。

## 4. 功能需求

### 4.1 异常层次（exceptions.py）

| 类名 | 父类 | 附加属性 | 场景 |
|------|------|----------|------|
| `SparkTechError` | `Exception` | `message`, `code` | 所有业务异常基类 |
| `ValidationError` | `SparkTechError` | `field` | 姓名/手机号校验 |
| `ConfigError` | `SparkTechError` | `key` | 环境变量缺失 |
| `DataLoadError` | `SparkTechError` | `path` | JSON 读写失败 |

### 4.2 utils 模块

| 模块 | 函数 | 行为 |
|------|------|------|
| `validators.py` | `validate_name` | 空则 `raise ValidationError` |
| | `validate_phone` | 位数不足则 `raise ValidationError` |
| | `normalize_phone` | 去非数字字符 |
| `io.py` | `load_json_file` | 文件不存在/JSON 坏 → `DataLoadError` |
| | `get_env` | 可选 `load_dotenv`；`required=True` 缺失 → `ConfigError` |

### 4.3 演示脚本

| 文件 | 必须演示 |
|------|----------|
| `demo_imports.py` | 绝对导入、`from sparktech import ...`、子包导入、`__name__` |
| `demo_exceptions.py` | try/except/else/finally、按类型捕获、`raise`、re-raise |

### 4.4 依赖（requirements.txt）

```
requests>=2.31.0,<3
python-dotenv>=1.0.0,<2
```

> 今日代码不强制调用 `requests`；为 Day 20 API 预留。`python-dotenv` 供 `get_env` 演示。

### 4.5 虚拟环境（setup_venv.sh）

脚本必须：

1. `python3 -m venv .venv`（或通过 `VENV_DIR` 覆盖）  
2. `pip install --upgrade pip`  
3. `pip install -r requirements.txt`  
4. 打印后续验收命令  

## 5. 非功能需求

- Python 3.10+  
- 教学入口脚本允许 `sys.path.insert(0, code_dir)`；库代码 **禁止** 在包内写 `sys.path` 黑魔法  
- 中文注释与 docstring  
- `verify_package.py` 非交互、退出码 0 表示通过
