## 1. `sys.path` 与 `PYTHONPATH`

`sys.path` 是 **list**，可在运行时修改（教学用）：

```python
import sys
print(sys.path[:3])
```

| 路径来源 | 典型位置 |
|----------|----------|
| 当前目录 | `''` 或脚本所在目录 |
| 标准库 | `lib/python3.x` |
| site-packages | `.venv/lib/.../site-packages` |

`PYTHONPATH` 环境变量会在启动时追加到 `sys.path`。

## 2. 包内相对导入深度

```python
# sparktech/utils/io.py
from ..exceptions import DataLoadError   # 上一级包
from .validators import strip_field        # 同级子包
```

| 符号 | 含义 |
|------|------|
| `.` | 当前包（utils） |
| `..` | 父包（sparktech） |
| `...` | 上两级（今日用不到） |

公司规范：对外 API 仍从 `sparktech` 根导入，相对导入仅包内使用。

## 3. `__all__` 与 `import *`

```python
# 不推荐在生产代码滥用
from sparktech import *
```

`__all__` 限制 `*` 导出的名字，但 **显式 import** 仍是最佳实践：

```python
from sparktech import validate_phone, ValidationError
```

---

## 4. 异常最佳实践清单

1. **具体优于宽泛**：先 `ValidationError`，再 `Exception`  
2. **库层 raise，UI 层 catch**：`validators` 不 `print`  
3. **保留异常链**：`raise NewError(...) from exc`  
4. **不用异常做正常流程**：`for/else`、返回值优先于抛异常控制循环  
5. **文档写明会抛什么**：docstring 列出 `Raises: ValidationError`

## 5. `setup_venv.sh` 逐行说明

```bash
set -euo pipefail   # 任一步失败即退出；-u 未定义变量报错
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

| 变量 | 用途 |
|------|------|
| `VENV_DIR` | 覆盖默认 `.venv` 目录名 |

Windows 学员：

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 6. `pip` 常用命令扩展

```bash
pip install requests==2.31.0      # 装指定版本
pip install -e .                  # 可编辑安装（Day 12）
pip uninstall requests -y
pip check                         # 检查依赖冲突
python -m pip install ...         # 明确用当前 python 的 pip
```

**坑**：系统同时存在 `pip` 与 `pip3`，激活 venv 后应使用 `python -m pip`。

## 7. `python-dotenv` 与安全

`.env` 示例：

```env
SPARKTECH_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.openai.com/v1
```

| 规则 | 原因 |
|------|------|
| `.env` 入 `.gitignore` | 防密钥泄漏 |
| 提供 `.env.example` | 文档化所需变量名 |
| 生产用环境变量注入 | K8s Secret、CI Variables |

`get_env` 在已安装 `python-dotenv` 时自动 `load_dotenv()`。

## 8. 循环导入（预习）

```text
a.py imports b.py
b.py imports a.py  →  半初始化或 ImportError
```

解法：

- 延迟导入（函数内部 import）  
- 抽取公共模块到第三文件  
- 重构依赖方向  

Day 6 四包若互相引用易踩坑；Day 10 统一 `sparktech` 后由 `exceptions` 作底层无依赖模块。

## 10. 与 LLM SDK 的 import 对照
