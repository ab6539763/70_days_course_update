# Day 15 补充讲义 · BPE、多模态 Token 与国产模型计价

## 1. BPE 合并过程（直觉版）

```text
初始词表: [a, b, c, d, ...]
语料统计: "ab" 出现频率极高
合并: 新增符号 "ab"
重复: "ab" + "c" → "abc"
最终: 常见词组变成单个 Token，生僻串拆成多个
```

**为何「Hello」可能是 1 Token，「㐀」可能是 3 Token**：后者在训练语料中罕见，未进入高频合并。

## 2. tiktoken 常用 API

```python
import tiktoken

# 按模型自动选 encoding
enc = tiktoken.encoding_for_model("gpt-4o")

# 显式指定（如 cl100k_base）
enc = tiktoken.get_encoding("cl100k_base")

ids = enc.encode("星火智服")
text = enc.decode(ids)
single = enc.decode([ids[0]])  # 看第一个 Token 长什么样
```

## 3. 多模态与工具 Token

| 类型 | 计费注意 |
|------|----------|
| 图片输入 | 按 patch/分辨率换算 Token（各厂商公式不同） |
| 音频 | 按时长或帧 |
| Function calling | 工具 schema 也占 prompt Token |

星火智服 V1 以文本为主；二期若上图，需单独查价目表。

## 4. 国产 API 计价差异

| 厂商 | 常见计费单位 | 备注 |
|------|--------------|------|
| DeepSeek | 元/百万 Token | 输入输出分列 |
| 通义千问 | 元/千 Token 或百万 | 注意单位换算 |

**课堂 mock 用美元价表**；交付小陈时注明币种与汇率。

## 5. context window 与成本

```text
窗口 128K ≠ 免费塞满
塞满 → 延迟↑ 单价×Token数↑ 摘要质量可能↓
```

RAG 策略：检索 Top-K 控制在 4K–8K Token 内，再留出生成空间。

## 6. 与 Day 16 的衔接

- `max_tokens` 限制输出上限 → 直接影响 completion 成本  
- `temperature` 高 → 同样 prompt 可能生成更长回答 → 间接增费  
- 流式 `stream=True` 不改变计费，只改变体验
