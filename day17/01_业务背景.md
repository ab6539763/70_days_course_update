## 1. 事件回顾

**关联**：Day 14 命令行助手、Day 15 Token 计费、Day 30 RAG 检索  

### 1.1 现场情况

周一晨会，产品小陈播放了预发环境客服机器人录屏：

| 现象 | 用户输入 | 模型输出 | 根因初判 |
|------|----------|----------|----------|
| 答非所问 | 「如何申请 API Key？」 | 输出年假政策全文 | Prompt 无任务指令，上下文污染 |
| 格式失控 | 「分类这条投诉」 | 先解释再输出 markdown 表格 | 缺少 JSON 输出约束 |
| 语言混杂 | 「翻译产品名」 | 中英夹杂 + 多余寒暄 | 无 output_format |
| 幻觉引用 | 「根据文档…」 | 文档中不存在的内容 | context 与 instruction 未分隔 |

李姐在工单评论：

> 「模型没问题，**Prompt 有问题**。Day 17 全员过一遍四要素：Instruction / Context / Input / Output。  
> 下午动手写 **10 条可复用模板**——翻译、摘要、改写、分类各覆盖。无 Key 走 mock，别耽误演示。」

### 1.2 与 Day 2 的呼应

Day 2 晚自习《Prompt 字符串预备营》已用 f-string 拼过 RAG 雏形。今日从「字符串能跑」升级到「**可评审、可版本化、可 A/B**」的 Prompt 工程。

| 维度 | Day 2 预备营 | Day 17 目标 |
|------|--------------|-------------|
| 拼接方式 | 手写 f-string | `PromptTemplate` 类 + `prompt_library/` |
| 示例 | 单条演示 | zero / one / few-shot 系统对比 |
| 输出 | 自由文本 | JSON schema 约束预演 |
| 安全 | 未涉及 | 分隔符隔离用户输入（Day 18 深化） |

## 3. 业务价值

星火智服下周要给销售团队演示「智能分拣 + 自动摘要」。如果 Prompt 质量不稳：

- 工单摘要会漏掉「紧急程度」  
- 意图路由错误会把投诉送进 FAQ 机器人  
- 多语言门店无法统一话术  

今日产出的 `prompt_library/` 将成为 **全团队 Prompt 规范的基线**。

## 4. 今日学习目标（业务语言）

1. 能画出 Instruction / Context / Input / Output 四要素关系图  
2. 能解释 zero-shot、one-shot、few-shot 的适用场景与成本  
3. 会用 `<<<input>>>` 类分隔符隔离用户输入  
4. 能在 Prompt 中嵌入 JSON 输出样例  
5. 完成 10 条可运行模板并通过验收脚本
