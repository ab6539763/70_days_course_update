## 1. 故事线：从培训作业到内部 PoC

Week 1 你们交付了通讯录 CLI、JSON 导出、函数拆包。Week 2 学了 OOP、继承多态、包结构与异常工程化。产品部小陈在周中评审时说：

> *「客户要的不是『能调一次 API』的脚本，而是**能驻留在终端里的助手**——销售同事问政策、问话术，要能连着聊、能清空、能存档给主管看。」*

张工在白板上画了三个框：

```text
┌─────────────┐    ┌──────────────┐    ┌─────────────┐
│ ChatMessage │ →  │ Session 列表  │ →  │ LLM Client  │
│  (Day 8)    │    │ 多轮 memory   │    │ mock / live │
└─────────────┘    └──────────────┘    └─────────────┘
        ↓                  ↓                  ↓
              JSON 持久化 (data/sessions/)
```

这就是 **Stage Project 1** 的业务价值：**把前两周的语法点串成可演示的 PoC**。

## 3. 为什么必须是「命令行」而不是网页？

PoC 阶段刻意选择 **CLI**：

1. **聚焦核心**：消息列表、持久化、异常——不被前端框架分散注意力  
2. **与 Week 1 衔接**：REPL 模式学员已熟悉（Day 3/6）  
3. **便于自动化测试**：stdin/stdout 可管道化验收  
4. **Day 20 再升 HTTP**：今日打好 `session` + `llm_client` 内核

## 5. 风险与约束

| 风险 | 缓解 |
|------|------|
| 学员无 API 额度 | 默认 mock；`.env.example` 说明可选 Key |
| 会话 JSON 损坏 | `DataLoadError` / `SessionStorageError` 友好提示 |
| 模块耦合过重 | PRD 强制六文件职责表 |
| 答辩时间紧 | `04_课堂讲义.md` 提供分步实现顺序 |
