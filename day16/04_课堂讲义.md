## 第一章 · 四大采样参数（09:00–10:30）

### 1.1 自回归生成回顾

模型每步预测 **下一个 Token 的概率分布**，再按策略采样：

```text
已生成: 「退款一般」
下一 token 候选: 「需要」「在」「3」… 各有一定概率
采样参数决定: 从分布中怎么选
```

### 1.2 temperature

| 值 | 效果 | 适用 |
|----|------|------|
| → 0 | 接近贪心，选最高概率 | 事实问答、政策引用 |
| 0.7 默认 | 适度多样 | 通用对话 |
| → 2 | 非常随机 | 创意写作（客服慎用） |

```python
# param_experiment.py 扫描示例
for t in [0.0, 0.3, 0.7, 1.2]:
    client.chat(messages, temperature=t)
```

### 1.3 top_p（核采样）

只从累积概率达到 `top_p` 的最小 token 集合中采样。

- `top_p=0.1`：极保守  
- `top_p=0.9`：常用平衡点  
- 与 temperature **一般二选一微调**

### 1.4 max_tokens

- 限制 **输出** Token 上限（不含输入）  
- 演示场景建议 256–512，避免长篇大论  
- 与 Day 15 成本：`completion_tokens ≤ max_tokens`

### 1.5 frequency_penalty

- 正值：惩罚已出现过的 token → **减少重复用语**  
- 负值：鼓励重复（少用）  
- 客服场景 0.2–0.5 可减轻「您好您好」式套话

▶ 运行：`python3 param_experiment.py --param temperature`

## 第二章 · system / user / assistant（10:30–12:00）

### 2.1 三角色职责

```python
messages = [
    {
        "role": "system",
        "content": (
            "你是星火智服官方客服助手。"
            "回答简洁，不超过 5 句。"
            "不确定的政策引导用户提交工单。"
        ),
    },
    {"role": "user", "content": "退款多久到账？"},
]
```

| 错误做法 | 后果 |
|----------|------|
| 把人设写在 user 里 | 多轮后模型忽略 |
| 没有 system | 口吻漂移、易过长 |
| assistant 历史造假 | 模型相信虚假上下文 |

### 2.2 与 Day 14 多轮助手

Day 14 `session.messages` 持续 append user/assistant；system 通常只在会话初始化时插入一次。

▶ 运行：`python3 role_messages_demo.py`

## 第三章 · stream=True 打字机（14:00–15:00）

### 3.1 为何需要流式

| 非流式 | 流式 |
|--------|------|
| 等完整 JSON | 首 token 到达即可展示 |
| 用户感觉「卡住」 | 逐字输出，体验更活 |

### 3.2 代码模式

```python
for chunk in client.chat_stream(messages, temperature=0.3):
    print(chunk, end="", flush=True)
print()  # 换行
```

mock 模式：`llm_compat` 将完整回复切分后 `yield`，并 `sleep` 模拟间隔。

▶ 运行：`python3 stream_demo.py`

## 第四章 · 参数对比报告（15:00–17:00）

### 4.1 实验设计

**控制变量**：同一 `prompt_id`、同一 `messages`、只改参数 preset。

```bash
python3 compare_params.py \
  --prompt-id customer_demo \
  --write-defaults
```

### 4.2 如何读报告

| 字段 | 看什么 |
|------|--------|
| response_text | 是否过长、是否重复、是否偏题 |
| completion_tokens | 成本与 max_tokens 关系 |
| latency_ms | 流式首字 vs 总时长 |
| preset_name | stable / creative / demo_balanced |

### 4.3 客户演示推荐配置

经对比后写入 `output/demo_defaults.json`：

```json
{
  "temperature": 0.3,
  "top_p": 0.9,
  "max_tokens": 512,
  "frequency_penalty": 0.3,
  "stream": true
}
```

**理由话术**：偏低温度保证政策类回答稳定；frequency_penalty 减少寒暄重复；流式降低等待焦虑。
