# Day 27 架构与设计 · Memory 策略

## 1. RunnableWithMessageHistory 架构

```text
用户输入 + session_id
        │
        ▼
┌───────────────────────────────┐
│ RunnableWithMessageHistory     │
│  1. get_session_history(id)    │
│  2. 注入 history 到 chain 输入  │
│  3. invoke 核心链              │
│  4. 写回 user/ai 到 history    │
└───────────────┬───────────────┘
                ▼
        prompt | llm | parser
```

## 2. History 工厂模式

```python
_STORE: dict[str, BaseChatMessageHistory] = {}

def get_session_history(session_id: str) -> BaseChatMessageHistory:
    if session_id not in _STORE:
        _STORE[session_id] = create_history(session_id)
    return _STORE[session_id]
```

`create_history` 根据 `SPARKTECH_MEMORY_MODE` 返回不同实现。

## 3. 三种策略对比

| 策略 | 类 | 优点 | 缺点 |
|------|-----|------|------|
| 全量 memory | `ChatMessageHistory` | 简单 | token 增长 |
| 窗口 window | `WindowChatMessageHistory` | 控 token | 丢远期细节 |
| 摘要 summary | `SummaryChatMessageHistory` | 保留要点 | 需摘要 LLM（mock 用拼接） |
| SQLite | `SQLChatMessageHistory` | 持久化 | 需 DB 文件 |

## 4. 与 Day 25 LangChainSession 对比
