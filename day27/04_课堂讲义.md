## 第一章 · 为什么需要 Memory（09:00–09:45）

多轮对话 = 每次调用都要带上历史 messages。Day 25 手写 `history` 列表易错；LangChain Memory 层负责：

- 读：从 store 取历史注入 prompt  
- 写：把本轮 user/ai 追加到 store  
- 裁：window / summary 控制长度

## 第三章 · RunnableWithMessageHistory（10:45–12:00）

[code/session_memory_chat.py](./code/session_memory_chat.py)：

```python
from langchain_core.runnables.history import RunnableWithMessageHistory

chain_with_history = RunnableWithMessageHistory(
    core_chain,
    get_session_history,
    input_messages_key="user_input",
    history_messages_key="history",
)

config = {"configurable": {"session_id": "user-001"}}
chain_with_history.invoke({"user_input": "你好"}, config=config)
```

**要点**：

- `input_messages_key` 对应当前轮用户字段  
- `history_messages_key` 对应 `MessagesPlaceholder` 变量名  
- `session_id` 必须通过 `configurable` 传入

## 第四章 · Window 与 Summary（14:00–15:00）

### 4.1 WindowChatMessageHistory

保留最近 `k` 对 human/ai，丢弃更早消息。适合客服短会话。

### 4.2 SummaryChatMessageHistory

超过 `max_messages` 时，将旧消息压缩为 `summary_text`（课堂 mock 用字符串拼接；生产可用 LLM 摘要链）。
