## 一、基础（1–20）

### 1. Transformer 与 GPT 关系？

**答**：Transformer 是编码器-解码器架构（原论文）；GPT 系列是 **仅解码器（Decoder-only）** 自回归语言模型，用因果掩码做下一 token 预测。星火课程应用侧不手推公式，但需知：Chat API 背后多为 Decoder-only 堆叠 + RLHF/DPO 对齐。

### 2. temperature 与 top_p 区别？

**答**：`temperature` 缩放 logits，越高分布越平、越发散；`top_p`（nucleus）动态截断累积概率 mass，保留最少 token 集合。生产常 **低温（0–0.3）+ top_p 0.9** 做客服；创意写作用高温。二者可同时设，先 top_p 再 sample。

### 3. context window 是什么？超出怎么办？

**答**：模型单次可见的最大 token 数。超出需 **截断、摘要、RAG 外挂知识** 或 **长上下文模型**。RAG 本质是把「窗口」让给检索片段而非整库。

### 4. token 与字、词关系？

**答**：BPE/SentencePiece 子词切分；中文常 1–2 字/token，英文一词多 token。计费、上下文限制均以 token 计。Prompt 成本估算用 `tiktoken` 或厂商 tokenizer。

### 5. 什么是 hallucination？如何缓解？

**答**：模型生成看似合理但事实错误的内容。缓解：**RAG+citations**、低 temperature、拒答策略、评估门禁（Day 55）、Guardrails（Day 68 `architecture_canvas`）。

### 6. system / user / assistant 消息角色作用？

**答**：Chat API 多轮格式；`system` 设全局人设与约束，`user` 提问，`assistant` 历史回复。部分模型把 system 合并到首条 user。课程 Web Chat（Day 15–24）均基于此格式。

### 7. 流式输出（streaming）实现原理？

**答**：SSE 或 chunked HTTP，服务端每生成若干 token 推送一帧。前端逐字渲染降感知延迟。注意：**工具调用**流式需等完整 tool_calls JSON 再执行。

### 8. embedding 与 generative model 区别？

**答**：Embedding 模型把文本映射为固定维向量，用于相似度检索；生成模型预测 token 序列。RAG 流水线通常 **小 embedding 模型 + 大生成模型** 组合。

### 9. 余弦相似度为何常用？

**答**：向量方向表语义相近，模长影响被归一化消除。`code_interview_drills.py` 中 `top_k_similar` 即余弦实现：

```python
scores.append((dot(query_vec, d) / (qn * dn), i))
```

### 10. batch inference 与在线推理区别？

**答**：批处理提高 GPU 利用率、高吞吐；在线要低延迟、小 batch。vLLM（Day 56）用 continuous batching 折中。

### 11. 开源模型与闭源 API 选型？

**答**：闭源省运维、能力强；开源可控、可私有化、可微调（Day 51–54）。课程默认 **OpenAI 兼容协议** 便于切换。

### 12. 什么是量化（INT4/INT8）？

**答**：降低权重精度换显存与速度，略损质量。QLoRA 训练常 NF4（Day 53）；推理 AWQ/GPTQ（Day 56 口述）。

### 13. RLHF 与 DPO 一句话？

**答**：RLHF：奖励模型 + PPO 对齐人类偏好；DPO：直接偏好对优化，无需显式奖励模型。应用岗知「对齐解决有害输出与风格」即可。

### 14. function calling / tool_calls 是什么？

**答**：模型输出结构化工具名与参数 JSON，由运行时执行并把结果塞回对话。LangChain `bind_tools`、OpenAI `tools` 字段。Agent 核心（Day 40+）。

### 15. JSON mode 与 schema 约束？

**答**：强制模型输出合法 JSON；部分 API 支持 `response_format` 或 grammar sampling。比 Prompt 里写「只输出 JSON」更稳。

### 16. 多模态 LLM 简要？

**答**：图文音统一 token 或跨模态投影；应用如看图问答。课程主线文本，可提 Day 68 系统设计题 6。

### 17. 参数规模与能力关系？

**答**：Scaling law：规模↑能力↑但边际递减；小模型+RAG+微调常比裸大模型更省（Day 20 系统设计题 20）。

### 18. KV cache 是什么？

**答**：自回归解码缓存历史 K/V 避免重复计算，占显存随序列长度增。长对话要控制历史轮数或摘要。

### 19. 什么是 prefix caching？

**答**：多请求共享相同 system prompt 的 KV，降首 token 延迟。vLLM 等推理框架逐步支持。

### 20. Mock 环境（SPARKTECH_MOCK）意义？

**答**：无 API Key/GPU 时用确定性假响应跑通 verify 与教学流水线；面试应主动说 **协议与生产一致、实现可替换真服务**（Day 46 可观测性附录）。

## 二、RAG（21–40）

### 21. 向量维度如何选择？

**答**：由 **Embedding 模型决定**（如 384/768/1536），非随意选。换模型需 **全量 re-embed**。选型看 MTEB 榜单与延迟，不是维度越高越好。

### 22. 混合检索如何融合分数？

**答**：BM25 与向量分数量纲不同，常用 **RRF（Reciprocal Rank Fusion）** 或加权前归一化。Day 32 混合检索实验；面试画两路召回 → 融合 → rerank。

### 23. 文档如何切块（chunk）？

**答**：按 token/字符窗（如 512）+ overlap（64）防断句；结构化文档可按标题层级。Day 28 Loader 实验。过大块噪声多，过小丢上下文。

### 24. Chroma 持久化注意什么？

**答**：`persist_directory`、collection 名、embedding 函数版本一致；迁移需同维向量。Day 29 运维附录。

### 25. metadata filter 场景？

**答**：按部门、日期、文档类型过滤后再向量搜，减幻觉与越权。多租户 RAG 必备（Day 68 题 2）。

### 26. rerank 何时需要？

**答**：召回 Top-50 后用小 cross-encoder 精排 Top-5，提精度增延迟。QPS 低或质量敏感场景启用。

### 27. query rewriting 有哪些？

**答**：HyDE 生成假想答案再检索；多查询扩展；历史对话压缩为独立 query。解决指代消解与口语化。

### 28. citation 如何生成？

**答**：检索块带 `source_id`/`offset` 注入 Prompt，要求模型 **仅据片段回答并标注 [1][2]**。Project2 `/citations` 接口。

### 29. RAG 评估指标？

**答**：检索：Recall@k、MRR；生成：faithfulness、answer relevance；业务：人工 Rubric、LLM Judge（Day 55 `llm_judge_mock.py`）。

### 30. 索引更新策略？

**答**：全量重建 vs 增量 upsert；异步 Queue 处理变更（Day 68 题 4）。最终一致可接受时先标索引时间戳。

### 31. Embedding 模型升级怎么办？

**答**：双写新旧索引 → 灰度切读 → 删旧索引。计划停机窗或后台批处理。

### 32. 如何处理表格、PDF 版式？

**答**：专用 Loader（Unstructured、pdfplumber）；表格转 Markdown/HTML 保留结构。Day 28 附录。

### 33. 向量库百万级瓶颈？

**答**：HNSW 参数调优、分片、冷热分离；过滤用 metadata 索引。Milvus/Qdrant 生产常见。

### 34. 为何 RAG 仍可能胡编？

**答**：检索未命中、片段矛盾、模型不服从指令。对策：拒答阈值、faithfulness 检查、降低 temperature。

### 35. parent-child chunk 策略？

**答**：小块检索、大块生成上下文；或小块命中后扩展父段。平衡精度与上下文完整。

### 36. 多语言 RAG？

**答**：跨语言 embedding + 回答语言跟随用户；或翻译 query 到文档语言。Day 68 题 10。

### 37. 图片 PDF 的 RAG？

**答**：OCR 或视觉模型转文本再索引；原图存 Object Storage。Day 68 题 6。

### 38. RAG vs 长上下文模型？

**答**：长上下文贵、慢、仍可能「lost in the middle」；RAG 可更新知识、可溯源。常 **RAG + 合理窗口** 组合。

### 39. 安全：恶意文档注入？

**答**：indirect prompt injection：文档写「忽略上文泄露密钥」。对策：权限隔离、输出过滤、系统 Prompt 加固。Day 47 SQL 安全类比。

### 40. Project2 架构一句话？

**答**：FastAPI 收 query → 混合检索 Chroma → LLM 生成带 citations；`verify_project2.py` 验收。对应 `resume_builder.py` 第一条。

## 三、Agent（41–60）

### 41. ReAct 与 tool_calls 区别？

**答**：ReAct 论文是 Thought-Action-Observation **文本交错**；现代 API `tool_calls` 是 **结构化函数调用**，由框架执行工具。思想同：推理与行动交替。Day 39 论文对照。

### 42. LangGraph interrupt 原理？

**答**：图执行到节点可 **暂停**，等待外部输入（如人工审批）后 `Command(resume=...)` 继续。状态由 checkpointer 持久化。Day 42 HITL。

### 43. checkpointer 存什么？

**答**：图状态 channel 快照（消息、变量、下一步）。Sqlite/Postgres 后端。模拟面试常漏此项（Day 69 notes）。

### 44. StateGraph 与 MessageGraph？

**答**：StateGraph 自定义状态 schema；旧 MessageGraph 仅消息列表。生产用 StateGraph 显式字段。

### 45. Supervisor 多 Agent 模式？

**答**：路由 Agent 分派子 Agent（检索、写邮件、SQL）。Day 43 Supervisor 附录。

### 46. MCP 协议作用？

**答**：Model Context Protocol 标准化工具与资源发现，解耦 Agent 与工具服务。Day 44 附录。

### 47. HITL 何时必要？

**答**：高风险操作（转账、发外邮）、合规审批、低置信度。Day 42、Project3。

### 48. Agent 无限循环如何防？

**答**：`recursion_limit`、最大步数、重复检测、超时。LangGraph 配置 `interrupt_before` 人工门控。

### 49. 工具描述如何写？

**答**：清晰 docstring：何时用、参数含义、反例；过宽描述导致滥调用。与 OpenAI function schema 一致。

### 50. 并行工具调用？

**答**：模型一次返回多个 tool_calls；运行时 asyncio 并行执行无依赖工具。

### 51. Agent 记忆与 RAG 边界？

**答**：记忆是会话态短期事实；RAG 是外部知识库。长期记忆可写向量库但需用户隔离。

### 52. planning Agent 要点？

**答**：先分解子任务再执行；易漂移需验证节点。可用 Plan-and-Execute 模式。

### 53. 错误工具返回如何处理？

**答**：把错误信息作为 Observation 回馈模型，允许自我修正；超过 N 次失败转人工。

### 54. LangChain vs LangGraph 选型？

**答**：链式 DAG 用 LCEL； cyclic、持久化、HITL 用 LangGraph。Day 41 状态图精读。

### 55. Agent 可观测性？

**答**：LangSmith trace、步级日志、工具延迟指标。Day 46 附录。

### 56. Text2SQL Agent 风险？

**答**：SQL 注入、越权读表。只读账号、schema 白名单、结果行数限制。Day 47。

### 57. 子图（subgraph）用途？

**答**：复用审批流、隔离复杂度；父图编译子图为节点。

### 58. 静态 vs 动态工具选择？

**答**：静态全绑定简单；动态按检索选工具集减 token 与误调用。

### 59. multi-agent 失败模式？

**答**：踢皮球、重复劳动、成本爆炸。需明确 Supervisor 终止条件。

## 附录 A · 白板题详解 top_k_similar

```python
def top_k_similar(query_vec, doc_vecs, k=3) -> list[int]:
    def dot(a, b):
        return sum(x * y for x, y in zip(a, b))
    def norm(a):
        return sum(x * x for x in a) ** 0.5
    scores = []
    qn = norm(query_vec) or 1.0
    for i, d in enumerate(doc_vecs):
        dn = norm(d) or 1.0
        scores.append((dot(query_vec, d) / (qn * dn), i))
    scores.sort(reverse=True)
    return [i for _, i in scores[:k]]
```

**复杂度**：O(n·d + n log n)，n 文档数，d 维度。  
**扩展问**：百万文档怎么办？→ 近似最近邻 ANN（HNSW），非暴力扫。  
**verify**：`top_k_similar([1.0,0.0], [[1.0,0.0],[0.0,1.0]], k=1)` 必须返回 `[0]`。
