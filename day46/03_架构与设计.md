# Day 46 架构与设计 · 稳定性分层

## 1. 防御纵深

```text
          用户请求
             │
             ▼
      ┌──────────────┐
      │  InputGuard  │  ← 第一道：注入/长度
      └──────┬───────┘
             ▼
      ┌──────────────┐
      │ CircuitBreaker│ ← 第二道：熔断
      └──────┬───────┘
             ▼
      ┌──────────────┐
      │  Agent Core  │  ← 第三道：max_rounds（业务层）
      └──────┬───────┘
             ▼
      ┌──────────────┐
      │ RetryWrapper │  ← 第四道：可重试错误
      └──────┬───────┘
             ▼
      ┌──────────────┐
      │ OutputGuard  │  ← 第五道：PII/空输出
      └──────┬───────┘
             ▼
          用户可见回答
```

## 2. Trace 模型（对齐 LangSmith）

| 字段 | 含义 |
|------|------|
| run_id | 唯一标识 |
| parent_id | 父 Span |
| span_type | agent / llm / tool / guard |
| latency_ms | 耗时 |
| error | 失败原因 |

## 3. 重试决策表

| 错误类型 | 重试 | 示例 |
|----------|------|------|
| RETRYABLE | 是 | timeout, 429 |
| FATAL | 否 | bad_schema, output_guard |
| 熔断打开 | 否 | 快速失败 |

## 4. 成本与延迟（设计约束）

- 每多一轮 LLM + tool ≈ +1–3s 延迟（教学 mock 忽略网络）  
- trace 存储：开发环境内存；生产用 LangSmith / OTel  
- 护栏正则应 **编译一次**，避免热路径重复 compile
