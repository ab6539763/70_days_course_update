## 第 2 节 · observability_demo 精读（60 min）

### 2.0 为何可观测性在护栏之前讲

无法度量就无法证明护栏有效。先建立 Run 树概念，再在 `guard_max_rounds` span 上看到 **error 字段**，形成闭环。

### 2.1 Span 数据模型

```python
@dataclass
class Span:
    name: str
    span_type: str = "chain"   # agent / llm / tool / guard
    run_id: str
    parent_id: str | None
    latency_ms: float
    inputs / outputs / error
    children: list[Span]
```

对齐 LangSmith：**Project → Run → Span 树**。

### 2.2 MockTracer.trace 上下文管理器

```python
with self.tracer.trace("llm_plan", span_type="llm", messages_count=2) as llm_span:
    ...
    llm_span.metadata["tokens_in"] = estimate_tokens(user_query)
    llm_span.finish({"plan": plan})
```

**要点**：

- `parent_id` 自动链接栈顶 Span  
- `finally` 中计算 `latency_ms`  
- 异常时 `span.finish(error=str(exc))`

```python
PII_PATTERNS = [
```

### 3.4 wrap_run 组合模式

```python
def wrap_run(self, user_text: str, runner: Callable) -> dict:
    inp = self.validate_input(user_text)
    if not inp.allowed: return {"blocked": True, "stage": "input", ...}
    raw = runner(inp.text)
    out = self.validate_output(raw)
    ...
```

**设计原则**：护栏在 Agent **外侧**，不污染业务 prompt。

### 4.1 错误分类

```python
class ErrorKind(str, Enum):
    RETRYABLE = "retryable"   # timeout, 429
    FATAL = "fatal"           # output_guard, bad_schema
```

### 4.2 指数退避

```python
delay = min(base_delay * (2 ** (attempt - 1)), max_delay)
```

避免 thundering herd —— 上游故障时所有 Agent 同时重试会雪上加霜。

### 4.3 CircuitBreaker 状态机

|------|------|------|
| Closed | 正常 | 允许请求 |
| Open | failures >= threshold | 快速失败 |
| Half-Open | cooldown 后 | 允许试探 |

```python
if not self.breaker.allow_request():
    return {"ok": False, "stage": "circuit_open", ...}
```

## 第 5 节 · 成本与延迟（30 min）

| 操作 | 额外成本 |
|------|----------|
| 每多一轮 LLM+tool | +1–3s 延迟（教学 mock 忽略网络） |
| 每次重试 | 全额 LLM 调用 |
| trace 存储 | 开发内存；生产 LangSmith 按量 |

**张工约束**：护栏正则 `re.compile` **只执行一次**（模块级），勿在热路径重复编译。

### 5.1 延迟预算表示例（星火智服 SLA）

| 阶段 | 预算 | 超限动作 |
|------|------|----------|
| input_guard | 10ms | — |
| 单轮 LLM | 3s | 换小模型 |
| 单工具 | 2s | 缓存 |
| 全 Agent | 15s | 降级 FAQ |
| output_guard | 10ms | — |

### 5.2 成本估算公式

```text
单次费用 ≈ (tokens_in + tokens_out) × 单价 × 重试次数
```

3 次重试 ≈ **3 倍** 费用 —— 解释为何 FATAL 不应重试。

## 第 7 节 · RetryAgentWrapper.invoke 逐步跟读（45 min）

对照 `retry_agent_wrapper.py` 第 108–159 行：

```python
def invoke(self, user_text: str) -> dict[str, Any]:
    inp = self.guardrails.validate_input(user_text)
    if not inp.allowed:
        return {"ok": False, "stage": "input_guard", ...}

    if not self.breaker.allow_request():
        return {"ok": False, "stage": "circuit_open", ...}

    for attempt in range(1, self.config.max_attempts + 1):
        try:
            answer = self.agent_fn(inp.text)
            out = self.guardrails.validate_output(answer)
            if not out.allowed:
                raise AgentError(ErrorKind.FATAL, "output_guard_blocked")
            self.breaker.record_success()
            return {"ok": True, "answer": out.text, "attempts": attempt, ...}
        except AgentError as exc:
            if exc.kind == ErrorKind.FATAL:
                break
            self._sleep_backoff(attempt)
```

**课堂练习**：将 `max_attempts` 改为 1，观察 flaky_agent 失败路径。
