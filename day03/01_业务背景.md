# Day 3 业务背景 · 培训小游戏与菜单壳

## 1. 事件回顾

**事件单号**：TRAIN-CLI-2026-0707  
**发起人**：人力资源部 · 培训组刘姐  
**关联**：DATA-QUALITY-2026-0706（Day 2 清洗工具已验收）  
**严重程度**：P2（不阻塞上线，但影响新人集训体验）

### 1.1 现场情况

周二下午，星火智服项目组新人集训进入第二周。刘姐找张工抱怨：

> 「你们清洗工具是给信息科用的，**太像后台脚本**了。集训要玩点能互动的——猜数字破冰、九九表当随堂测、统一菜单进各小游戏。最好以后智服助手也能用同一套菜单逻辑。」

张工当场在白板上画了三块：

```text
  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
  │ 猜数字游戏   │   │ 九九乘法表   │   │ 主菜单壳     │
  │ while 循环   │   │ for + range  │   │ /clear /exit │
  └─────────────┘   └─────────────┘   └─────────────┘
         │                 │                 │
         └─────────────────┴─────────────────┘
                           │
                    Day 14 命令行 AI 助手
```

晨会原话：

> 「Day 1 卡片空输入你们用占位符糊弄过去了；Day 2 清洗工具里已经有个 `while True` 读多行。今天把**分支和循环**学透，交付三个 CLI 程序。菜单里命令以斜杠开头——`/exit` 退出、`/clear` 清屏——这是 Day 14 多轮对话助手的命令约定，今天先练壳子。」

### 1.2 业务影响

- 集训破冰环节缺少标准化互动程序，讲师每次临时写脚本  
- 菜单不统一，学员切换小游戏体验割裂  
- 若不掌握循环，Day 4 待办列表、Day 14 多轮对话都无法实现「直到用户退出」

### 1.3 与 Day 2 的对比

| 维度 | Day 2 文本清洗 | Day 3 培训 CLI |
|------|----------------|----------------|
| 核心语法 | 字符串方法、f-string | if/elif/else、while、for |
| 交互模式 | 批处理 + 是否继续 | 游戏回合、菜单路由 |
| 退出方式 | `y/n` 询问 | `/exit` 命令（预埋） |
| 用户 | 信息科王工 | 培训组 + 全体集训生 |

## 3. 与大模型开发的隐性联系

| 今日循环/分支 | 日后场景 |
|---------------|----------|
| `while True` 主循环 | Day 14 聊天 REPL，直到 `/exit` |
| `if/elif` 命令路由 | `/clear` 清历史、`/help` 列命令 |
| `for` + `range` | 批量处理 messages、遍历检索结果 |
| `break` / `continue` | 跳过非法输入、提前结束生成流 |
| 嵌套条件 | 根据角色 + 内容决定是否调用工具 |

产品部补充：智服后台「训练小游戏」入口将来嵌入内网，今日 CLI 是 MVP。

## 4. 今日学习目标（业务语言）

1. 用 `if/elif/else` 处理用户不同输入，告别 Day 1 占位符  
2. 用 `while` 实现「猜错继续、空输入重试」  
3. 用 `for` + `range` 生成九九表与批量输出  
4. 交付带 `/clear`、`/exit` 的菜单壳，通过刘姐验收  
5. 晚间完成 2 道 LeetCode Easy，巩固循环思维
