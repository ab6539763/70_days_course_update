# Day 54 附录 · LLaMA-Factory 训练排错表

> 真机训练与 mock 流水线通用；配合 `09_附录_LLaMAFactory真机手册.md` 现场查阅。

---

## 启动与环境

| 症状 | 可能原因 | 处理步骤 |
|------|----------|----------|
| `command not found: llamafactory-cli` | 未安装 | `pip install llamafactory` |
| `CUDA not available` | 无驱动 / CPU 环境 | 用 `mock_llamafactory_train.py` |
| 模型下载超时 | 网络 | `HF_ENDPOINT` 镜像；预下载到缓存 |
| `trust_remote_code` 报错 | Qwen 需信任远程代码 | yaml 设 `trust_remote_code: true` |

---

## 数据集与配置

| 症状 | 可能原因 | 处理步骤 |
|------|----------|----------|
| `Dataset sparktech_cs not found` | dataset_info 未注册 | 检查 `dataset_info.json` 键名与 yaml `dataset` 一致 |
| `File not found: train.jsonl` | 路径错误 | 确认 `../day52/code/data/train.jsonl` 存在；先跑 `verify_day52` |
| 列映射错误 | columns 不匹配 | prompt→instruction, query→input, response→output |
| 样本数为 0 | jsonl 空或全被过滤 | `wc -l train.jsonl`；重跑 `split_dataset.py` |
| template 不匹配 | 模型与模板不一 | Qwen 模型必须用 `template: qwen` |

---

## 训练过程

| 症状 | 可能原因 | 处理步骤 |
|------|----------|----------|
| CUDA OOM | 显存不足 | QLoRA `quantization_bit: 4`；batch=1；cutoff_len 512 |
| loss 不下降 | lr 过小 / 数据问题 | 试 2e-4；检查 output 是否过短或重复 |
| loss NaN | lr 过大 / 脏数据 | 降 lr；查异常字符、空 output |
| loss 骤降后爆炸 | 学习率过高 | 减 lr；加 warmup |
| train loss 极低 val 高 | 过拟合 | 加 dropout；减 epoch；扩数据 |
| 训练极慢 | CPU 误用 | `nvidia-smi` 确认 GPU 占用 |
| 中断后如何续训 | — | `resume_from_checkpoint` 指向 output 目录 |

---

## 产物与验收

| 症状 | 可能原因 | 处理步骤 |
|------|----------|----------|
| 无 `adapter_config.json` | 未跑完 save_steps | 减小 save_steps 或等训练结束 |
| `peft_type` 不是 LORA | 配置错误 | yaml `finetuning_type: lora` |
| verify 失败 yaml | 文件被改坏 | 对照仓库默认 `sparktech_qwen_lora.yaml` |
| mock 通过但真机话术差 | mock 无真实权重 | 正常；需 GPU 真训 + Day55 评估 |
| adapter 太大无法提交 | 真机权重数百 MB | git-lfs 或只提交 config |

---

## 推理冒烟

| 症状 | 可能原因 | 处理步骤 |
|------|----------|----------|
| 回复像基座 | adapter 未加载 | chat 命令指定 `--adapter_name_or_path` |
| 乱码 | template 错误 | 统一 qwen 模板 |
| 无视 instruction | 训练数据前缀不一致 | 对齐「作为星火智服客服回复」前缀 |
| 编造政策数字 | 未接 RAG | Hybrid：先检索再生成 |

## 环境变量备忘

| 变量 | 用途 |
|------|------|
| `SPARKTECH_MOCK=1` | 教学 mock，跳过 GPU |
| `CUDA_VISIBLE_DEVICES=0` | 指定单卡 |
| `HF_ENDPOINT` | 模型下载镜像 |
| `WANDB_DISABLED=true` | 关闭 wandb 报错 |

## 日志关键词 grep

```bash
grep -i "error\|oom\|cuda\|dataset" train.log
tail -f output/sparktech_lora/trainer_log.jsonl
```

| 日志片段 | 含义 |
|----------|------|
| `OutOfMemoryError` | 见 OOM 行 |
| `Cannot find dataset` | dataset_info |
| `NCCL` | 多卡通信问题 |
| `loss: nan` | 学习率 / 数据 |

## 与 verify 脚本对照

`verify_day54.py` 不检查 loss 数值，只检查：

1. yaml 含 `lora_rank`  
2. mock 产出 `adapter_config.json` 且 `peft_type=LORA`  

真机问题需结合本表 + `trainer_log.jsonl` 人工判读。
